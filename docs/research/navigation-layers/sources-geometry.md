# Источники геометрии и микроконтроля

Проверены 4 ноября 2026 года. Объём — целевой обзор, не систематическая оценка всех any-angle алгоритмов. Код не копируется в MIT ядро, сторонние игры не запускались. Номера G### независимы от реестра движковых источников соседнего отчёта.

## Связь существенных выводов

| Вывод | Основание | Статус |
| --- | --- | --- |
| CG01: сеточный поиск совместим с any-angle результатом | G001, контраст G002/G003 | Наблюдение источников |
| CG02: LOS не доказывает, что срез выгоден при разных весах | G001 §8.2, G006 | Наблюдение; необходимость cost-aware smoothing для OpenRTS — вывод |
| CG03: ширина body и дискретизация маршрута — разные параметры | G004, G005 | Инженерный вывод; конкретный OpenRTS clearance ещё требует реализации |
| CG04: coarse среднее не заменяет топологию порталов | G005 + пример узкой стены в отчёте | Инженерный вывод, не теорема из benchmark |
| CG05: AoE geometry и поисковая penalty projection должны быть независимы | Требования пользователя; практический broadphase/narrowphase G010 | Предложение для OpenRTS; общий projector в addon не обнаружен |
| CG06: в addon есть части для ручного stutter step, но не подтверждены все приёмы | G008/G009 + отсутствие собственного playtest | Ограниченное наблюдение кода |
| CG07: точность координат недостаточна без swept безопасности и правил действий | Анализ нашей модели и перечисленные регрессионные сценарии | Требование к будущей реализации/проверкам |

Из G001–G011 не следует межплатформенный determinism OpenRTS, способность обслуживать 10000 юнитов или отсутствие заторов. Это подтверждается только отдельными собственными проверками и замерами.
