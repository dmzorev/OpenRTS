# Численная модель и исполнение симуляции

3 ноября 2026 года. Задача — воспроизводимое обновление 10000+ наземных объектов, независимое от Godot, FPS и времени завершения фоновых работ. Первый сценарий измеряет прямое движение; навигация и боевые взаимодействия требуют собственных решений.

| Вариант | Преимущество | Цена для текущей задачи |
| --- | --- | --- |
| float или double | Удобные геометрические операции и большой диапазон | Потребуются дополнительные гарантии воспроизводимости всех используемых операций и платформ |
| Целые координаты клеток | Простые операции | Недостаточная точность движения между клетками |
| Int32 с масштабом 1024 | Компактные позиции, определённые округления, точность 1/1024 клетки | Нужно ограничить диапазон и явно использовать Int64 для произведений |
| Int64 с масштабом | Больший диапазон координат | Более крупные структуры; для безопасных произведений больших значений понадобятся дополнительные ограничения или более широкая арифметика |

Выбран Int32 с масштабом 1024, положительными наземными координатами и максимальным размером стороны `2^29` raw единиц, то есть 524288 клеток. Для двух наземных осей сумма квадратов разностей не превышает `2^59`; максимальное произведение разности и шага `2^20` не превышает `2^49`. Промежуточный Int64 оставляет запас. Высота хранится отдельно и пока не участвует в наземной маршрутизации.

Прямое движение использует целочисленный квадратный корень с округлением длины вверх. Компоненты шага округляются к нулю, поэтому результирующий шаг не превышает установленную скорость. При минимальной скорости и диагональном направлении выбирается один шаг по преобладающей оси, чтобы объект не застревал. Квантование может давать небольшую погрешность направления и скорости; накопление дробных остатков и более сложная кинематика пока не требуются.

Переполнение координат не является допустимым игровым результатом. Границы проверяются при создании мира и при приёме команд. Для RNG, напротив, арифметика UInt64 намеренно оборачивается в `unchecked`. Эти режимы C# имеют разные определённые последствия. [Документация C#](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/statements/checked-and-unchecked).

**Случайность.** Используется небольшой фиксированный SplitMix64 с явным 64-битным состоянием. Семейство и эталонные реализации описаны на [странице автора](https://prng.di.unimi.it/); алгоритм и public-domain уведомление также доступны в [исходниках Metall от LLNL](https://software.llnl.gov/metall/api/random_8hpp_source.html). C# реализация проверяется известными векторами. Алгоритм не предназначен для криптографии.

Scatter получает один seed из мирового RNG и создаёт локальный поток по seed и устойчивому EntityId. Это обеспечивает одинаковые цели для логически одинаковых миров даже при разном порядке объектов в плотном массиве. Это не заявление о статистически независимых, непересекающихся потоках для произвольных научных задач.

**Хранение.** Плотный массив структур и словарь ID → индекс отделяют логический ID от размещения. Удаление переносит последний элемент в свободный слот, ID не переиспользуются. Текущие операции движения независимы для отдельных объектов. Общие взаимодействия будущих систем должны получить определённые правила конфликтов. Хеш сортирует записи по ID и включает всё текущее авторитетное состояние; порядок словаря не используется.

**Передача данных.** Три переиспользуемых буфера публикуют предыдущую и текущую позиции каждого объекта. Читатель удерживает lease и освобождает его после подготовки представления. Producer не изменяет закреплённый буфер; краткая блокировка защищает выбор слота и копирование, но не весь рендер. ReadOnlySpan запрещено сохранять после освобождения lease. Если свободных слотов нет, пропускается графическая публикация, а не тик.

События идут независимо от кадров. Удаление содержит последнюю позицию и тип объекта. Очередь ограничена; переполнение останавливает сессию с ошибкой вместо потери событий. Активная сцена изменяется только из основного потока Godot. [Ограничения API Godot](https://docs.godotengine.org/en/stable/tutorials/performance/thread_safe_apis.html).

**Представление.** Один плоский float буфер MultiMesh переиспользуется и передаётся пакетом. При уменьшении числа сущностей меняется VisibleInstanceCount, а ёмкость сохраняется. Float преобразования и интерполяция принадлежат представлению. Одна область видимости MultiMesh остаётся ограничением: для большой карты нужны чанки. [MultiMesh](https://docs.godotengine.org/en/stable/classes/class_multimesh.html).

На расстояниях, близких к предельному размеру мира, float представления уже не сохраняет точность raw координат ядра. Для таких карт потребуется вычитание локального начала координат до преобразования в float. Это не влияет на точность текущего авторитетного состояния; floating origin в стенде пока не реализован.

**Измерение.** [Исходные результаты](measurements.json) содержат один локальный Release запуск на Apple M3 Max: 64 тика прогрева и 128 измеряемых тиков на профиль. Все объекты направлены к дальнему краю мира и продолжают движение в конце измерения. Размер границ — 4096 × 4096 клеток; это не загруженная карта из 16 миллионов terrain ячеек.

| Объекты | p50 тика, мс | p95 тика, мс |
| --- | --- | --- |
| 1000 | 0,1536 | 0,2002 |
| 10000 | 0,5353 | 0,5746 |
| 100000 | 4,6658 | 5,1387 |

Измеряется только World.Step, без кадров, хеширования, маршалинга в Godot, навигации, столкновений и боя. Общие managed аллокации за измерение — 72, 72 и 328 байт соответственно; первая команда включает создание буфера. Отдельная проверка установившегося движения на 10000 объектах подтверждает ноль managed аллокаций непосредственно внутри Step. Это не обещание нулевых аллокаций всего приложения или определённого FPS будущей игры.

Следующий исследовательский вопрос — массовые маршруты и локальные конфликты движения. Профиль должен включать узкий проход, динамические препятствия и массовую смену приказа, а сравнение — число рабочих потоков и момент применения результатов. Полноценное SoA, более сложный RNG или другая арифметика вводятся при выявленной необходимости и с повторной проверкой воспроизводимости.
