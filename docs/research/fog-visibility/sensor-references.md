# Сенсоры и память игрока: разбор референсов

**Статус:** исследование исходников, 9 ноября 2026. Дополняет [первый обзор fog](README.md); выводы для OpenRTS и этапы находятся в [проекте F2+F3](signatures-and-knowledge.md). Игры здесь не запускались, производительность референсов не измерялась.

## Версии и область проверки

| Источник | Проверенная версия | Что прослежено |
| --- | --- | --- |
| OpenRA | `9636b63eaee62fcb60ef2e896e7985bdf2f1ee68`, локальный checkout без изменений | Visibility modifiers → cloak detectors → fog; frozen buildings → UI/targeting; стандартный radar widget |

Удалённые версии закреплены через GitHub commit endpoint и проверены по файлам на SHA. Первичный просмотр Recoil по `master` имел другие номера строк; ссылки ниже относятся к закреплённой версии. Архив 0 A.D. заканчивается в 2024 году и не описывает текущую разработку игры. GPL-исходники используются для понимания поведения; их код и построчный перевод в MIT-проект не переносятся.

## OpenRA: независимые причины скрытности и отдельный frozen actor

**Факт.** `Actor.CanBeViewedByPlayer` сначала требует успеха **всех** `IVisibilityModifier`, затем проверяет default visibility. Каждый активный `Cloak` пропускает союзника либо ищет хотя бы один союзный `DetectCloaked` с пересечением `DetectionTypes` и подходящим расстоянием. Поэтому внутри одного cloak действует «любой подходящий тип», а между двумя cloak — «преодолеть оба ограничения». Разные детекторы могут преодолеть разные cloak. Детектор сам по себе не открывает fog. [Actor.cs:511–519](https://github.com/OpenRA/OpenRA/blob/9636b63eaee62fcb60ef2e896e7985bdf2f1ee68/OpenRA.Game/Actor.cs#L511-L519), [Cloak.cs:297–305](https://github.com/OpenRA/OpenRA/blob/9636b63eaee62fcb60ef2e896e7985bdf2f1ee68/OpenRA.Mods.Common/Traits/Cloak.cs#L297-L305).

Окружение может выдавать condition своим token: `GrantConditionOnTerrain` проверяет terrain, включая изменение под неподвижным объектом; уход снимает именно этот token. В `Cloak.IsVisible` поиск проходит по `ActorsWithTrait<DetectCloaked>()`, без пространственного broad phase внутри этой функции. Типы строковые на уровне конфигурации, но `BitSet<T>` использует `BigInteger`, а не обязательные 64 бита. [GrantConditionOnTerrain.cs:45–64](https://github.com/OpenRA/OpenRA/blob/9636b63eaee62fcb60ef2e896e7985bdf2f1ee68/OpenRA.Mods.Common/Traits/Conditions/GrantConditionOnTerrain.cs#L45-L64), [Actor.cs:583–606](https://github.com/OpenRA/OpenRA/blob/9636b63eaee62fcb60ef2e896e7985bdf2f1ee68/OpenRA.Game/Actor.cs#L583-L606), [BitSet.cs](https://github.com/OpenRA/OpenRA/blob/9636b63eaee62fcb60ef2e896e7985bdf2f1ee68/OpenRA.Game/Primitives/BitSet.cs).

**Факт.** `FrozenUnderFog` создаёт отдельный `FrozenActor` на игрока для здания. В нём есть известные owner, HP, tooltip, target types/positions, footprint и отдельные renderables. Это не единый атомарный снимок всех полей на каждом видимом тике: обычный fog-путь вызывает `RefreshState` при возвращении прямой видимости, а renderables захватывает отдельно при её потере. [FrozenUnderFog.cs:64–112](https://github.com/OpenRA/OpenRA/blob/9636b63eaee62fcb60ef2e896e7985bdf2f1ee68/OpenRA.Mods.Common/Traits/Modifiers/FrozenUnderFog.cs#L64-L112), [133–159](https://github.com/OpenRA/OpenRA/blob/9636b63eaee62fcb60ef2e896e7985bdf2f1ee68/OpenRA.Mods.Common/Traits/Modifiers/FrozenUnderFog.cs#L133-L159), [FrozenActorLayer.cs:36–153](https://github.com/OpenRA/OpenRA/blob/9636b63eaee62fcb60ef2e896e7985bdf2f1ee68/OpenRA.Game/Traits/Player/FrozenActorLayer.cs#L36-L153).

Флаг `Hidden` отдельно учитывает cloak: иначе ghost мог бы выдать позицию через tooltip/автовыбор цели. Скрытая смерть оригинала не обязана сразу удалить память чужого игрока; мёртвый frozen actor убирается после возвращения соответствующей видимости. Смена владельца имеет специальное обновление для прежнего owner. При изменении shroud пространственные bins отмечают затронутые frozen actors, хотя общий tick-проход по записям остаётся. [FrozenActorLayer.cs:260–340](https://github.com/OpenRA/OpenRA/blob/9636b63eaee62fcb60ef2e896e7985bdf2f1ee68/OpenRA.Game/Traits/Player/FrozenActorLayer.cs#L260-L340), [FrozenUnderFog.cs:172–185](https://github.com/OpenRA/OpenRA/blob/9636b63eaee62fcb60ef2e896e7985bdf2f1ee68/OpenRA.Mods.Common/Traits/Modifiers/FrozenUnderFog.cs#L172-L185).

**Ограничение сравнения.** Стандартный radar здесь означает прежде всего minimap: `RadarWidget` отбрасывает `FogObscures(actor)` до чтения `IRadarSignature`. Это не BAR-подобное независимое поле обнаружения. Targeting реального/frozen actor имеет собственные проверки, а не общий API знания. [RadarWidget.cs:423–439](https://github.com/OpenRA/OpenRA/blob/9636b63eaee62fcb60ef2e896e7985bdf2f1ee68/OpenRA.Mods.Common/Widgets/RadarWidget.cs#L423-L439), [Target.cs:110–120](https://github.com/OpenRA/OpenRA/blob/9636b63eaee62fcb60ef2e896e7985bdf2f1ee68/OpenRA.Game/Traits/Target.cs#L110-L120), [AutoTarget.cs:365–409](https://github.com/OpenRA/OpenRA/blob/9636b63eaee62fcb60ef2e896e7985bdf2f1ee68/OpenRA.Mods.Common/Traits/AutoTarget.cs#L365-L409).

**Вывод для OpenRTS.** Полезны tokens причин, AND/OR-семантика скрытности и отдельная память. Полный scan всех detector для каждого скрытого actor не принимаем за доказанное решение для 10000 объектов. Объединение требований разных физических детекторов — отдельная игровая policy, а не естественное следствие набора строк.

## Recoil/BAR: контакт, опознание и наведение — разные права

**Факт.** В Recoil есть отдельные поля los/airLos/radar/sonar/seismic/jammer/sonarJammer. `InLos(unit, allyTeam)` учитывает cloak; `InRadar(unit, allyTeam)` независимо проверяет radar/sonar stealth и jammer. Cloak сам по себе не означает radar stealth. Проверка radar по позиции и по объекту различается: только объектная знает его свойства. Бинарное глушение зависит от настроек и команд; это не универсальная модель мощности сигнала. [LosHandler.cpp:870–997](https://github.com/beyond-all-reason/RecoilEngine/blob/bb35233187fe7c25a1f45034c66ece77d7e8989f/rts/Sim/Misc/LosHandler.cpp#L870-L997).

**Факт.** Четыре бита разделяют current optical (`INLOS`), current radar (`INRADAR`), прошлое визуальное наблюдение (`PREVLOS`) и непрерывное сопровождение после него (`CONTRADAR`). Оптика выставляет все четыре; потеря оптики при сохранении radar оставляет известность типа. Потеря обоих снимает `CONTRADAR`, сохраняя `PREVLOS`. `IsUnitTyped` требует оптику либо `PREVLOS+CONTRADAR`: новый radar-only захват после разрыва не восстанавливает тип автоматически. [Unit.h:45–58](https://github.com/beyond-all-reason/RecoilEngine/blob/bb35233187fe7c25a1f45034c66ece77d7e8989f/rts/Sim/Units/Unit.h#L45-L58), [Unit.cpp:933–954](https://github.com/beyond-all-reason/RecoilEngine/blob/bb35233187fe7c25a1f45034c66ece77d7e8989f/rts/Sim/Units/Unit.cpp#L933-L954), [LuaUtils.cpp:1882–1892](https://github.com/beyond-all-reason/RecoilEngine/blob/bb35233187fe7c25a1f45034c66ece77d7e8989f/rts/Lua/LuaUtils.cpp#L1882-L1892).

Доступ к типу требует typed, к HP — optical; текущий radar-контакт допускает позицию с ошибкой. Ошибка вычисляется относительно **живой истинной позиции**, а не сохранённого снимка, поэтому сама по себе не заменяет проверку доступа. Это специализированная битовая модель, не общий набор per-field timestamps/TTL. [LuaSyncedRead.cpp:528–559](https://github.com/beyond-all-reason/RecoilEngine/blob/bb35233187fe7c25a1f45034c66ece77d7e8989f/rts/Lua/LuaSyncedRead.cpp#L528-L559), [4052–4178](https://github.com/beyond-all-reason/RecoilEngine/blob/bb35233187fe7c25a1f45034c66ece77d7e8989f/rts/Lua/LuaSyncedRead.cpp#L4052-L4178).

`CWeapon.TestTarget` принимает current LOS либо radar, а при вычислении точки наведения используется разрешённая ошибка позиции. Таким образом, неопределённость контакта влияет и на бой. [Weapon.cpp:1039–1104](https://github.com/beyond-all-reason/RecoilEngine/blob/bb35233187fe7c25a1f45034c66ece77d7e8989f/rts/Sim/Weapons/Weapon.cpp#L1039-L1104), [1454–1461](https://github.com/beyond-all-reason/RecoilEngine/blob/bb35233187fe7c25a1f45034c66ece77d7e8989f/rts/Sim/Weapons/Weapon.cpp#L1454-L1461).

**Граница движок/игра.** Lua `SetUnitSensorRadius` перечисляет семь встроенных имён; произвольная строка не создаёт новый native канал. BAR отдельно задаёт правила jammer/sonar/cloak; его `armspy` явно сочетает cloak, radar stealth и sonar stealth. Поэтому общую невидимость конкретного юнита нельзя приписывать одному cloak или одному только движку. [LuaSyncedCtrl.cpp:3908–3947](https://github.com/beyond-all-reason/RecoilEngine/blob/bb35233187fe7c25a1f45034c66ece77d7e8989f/rts/Lua/LuaSyncedCtrl.cpp#L3908-L3947), [BAR modrules.lua:52–56](https://github.com/beyond-all-reason/Beyond-All-Reason/blob/964408d7e04d0da90fe2035c325ddefd775363d5/gamedata/modrules.lua#L52-L56), [armspy.lua:13–41](https://github.com/beyond-all-reason/Beyond-All-Reason/blob/964408d7e04d0da90fe2035c325ddefd775363d5/units/ArmBots/T2/armspy.lua#L13-L41).

**Вывод для OpenRTS.** Стоит заимствовать разделение прав и явную policy сохранения идентификации. Произвольные сигнатуры и общую память нужно проектировать отдельно. Нельзя автоматически унаследовать Recoil-право стрелять по radar EntityId: сначала нужно определить допустимую точку наведения и скрываемые поля.

## Generals Zero Hour: периодические проверки и удержание обнаружения

**Факт.** В просмотренном пути detector задаёт `DetectionRate`, отдельный `DetectionRange`, фильтры отношений/категорий и допустимость работы внутри контейнера. При создании фаза обновления распределяется игровым RNG; на обновлении используется пространственный `iterateObjectsInRange`, затем `markAsDetected(updateRate+1)`. Это позволяет пережить интервал до следующей проверки. [StealthDetectorUpdate.cpp:62–94](https://github.com/electronicarts/CnC_Generals_Zero_Hour/blob/0a05454d8574207440a5fb15241b98ad0b435590/GeneralsMD/Code/GameEngine/Source/GameLogic/Object/Update/StealthDetectorUpdate.cpp#L62-L94), [146–208](https://github.com/electronicarts/CnC_Generals_Zero_Hour/blob/0a05454d8574207440a5fb15241b98ad0b435590/GeneralsMD/Code/GameEngine/Source/GameLogic/Object/Update/StealthDetectorUpdate.cpp#L146-L208), [305–306](https://github.com/electronicarts/CnC_Generals_Zero_Hour/blob/0a05454d8574207440a5fb15241b98ad0b435590/GeneralsMD/Code/GameEngine/Source/GameLogic/Object/Update/StealthDetectorUpdate.cpp#L305-L306).

`markAsDetected` продлевает `m_detectionExpiresFrame`; периодический stealth-update меняет `OBJECT_STATUS_DETECTED`. В этом пути срок — поле объекта, не отдельная запись знания каждого наблюдателя. Нельзя переносить его как готовую per-player сенсорную модель. [StealthUpdate.cpp:779–807](https://github.com/electronicarts/CnC_Generals_Zero_Hour/blob/0a05454d8574207440a5fb15241b98ad0b435590/GeneralsMD/Code/GameEngine/Source/GameLogic/Object/Update/StealthUpdate.cpp#L779-L807), [870–914](https://github.com/electronicarts/CnC_Generals_Zero_Hour/blob/0a05454d8574207440a5fb15241b98ad0b435590/GeneralsMD/Code/GameEngine/Source/GameLogic/Object/Update/StealthUpdate.cpp#L870-L914).

**Вывод для OpenRTS.** Период и сглаживающий срок — полезная опция радара, но меняют игровую задержку обнаружения. Начать с каждого тика, затем сравнить периоды и детерминированные фазы. Удерживать следует разрешённое измерение/сопровождение; обновлять истинную позицию под видом старого измерения нельзя.

## 0 A.D.: память копирует разрешённые компоненты

**Факт.** `Fogging.LoadMirage(player)` создаёт игроку mirage, копирует owner/позицию/поворот/визуальные параметры и вызывает `CopyComponent` для выбранных компонентов, включая Health/Identity. `Mirage.CopyComponent` получает специальное представление компонента, а не обычную живую ссылку на него. При уничтожении исходной сущности fogged mirage может сохранить память с невалидным parent; после возвращения видимости он удаляется. [Fogging.js:63–131](https://github.com/0ad/0ad/blob/61a3b9507d974084e6badb88a0826bd89a6d5b8b/binaries/data/mods/public/simulation/components/Fogging.js#L63-L131), [172–214](https://github.com/0ad/0ad/blob/61a3b9507d974084e6badb88a0826bd89a6d5b8b/binaries/data/mods/public/simulation/components/Fogging.js#L172-L214), [Mirage.js:50–76](https://github.com/0ad/0ad/blob/61a3b9507d974084e6badb88a0826bd89a6d5b8b/binaries/data/mods/public/simulation/components/Mirage.js#L50-L76).

**Вывод для OpenRTS.** Память должна содержать копии наблюдавшихся данных и переживать удаление backing entity. Но отдельные полноценные ECS-сущности на каждую пару объект×игрок не обязательны: для нашей пакетной графики сначала достаточно компактных записей знания и опубликованных poses.

## Что сравнение установило, а что остаётся гипотезой

| Вопрос | Установлено чтением | Предложение для OpenRTS |
| --- | --- | --- |
| Cloak против radar | Recoil разделяет optical cloak и radar stealth | Независимые каналы и ограничивающие их причины |
| Несколько camouflage | OpenRA AND-ит cloak modifiers, OR-ит типы внутри одного | Явные правила композиции, без случайного раскрытия через один tag |
| Тип/HP/позиция | Recoil выдаёт разные права | Несколько групп фактов с собственной свежестью |
| Память умершего объекта | OpenRA/0 A.D. могут сохранять чужой ghost | Обновлять память наблюдениями, подтверждать отсутствие отдельно |
| Оптимизация | Есть пространственный запрос, периодические проверки и специальные кеши | Выбрать backend по отдельным замерам, не обещать ускорение заранее |
| Универсальная система | Ни один просмотренный путь не совпадает целиком с предложенной моделью | Общая схема observation → knowledge, небольшие конкретные реализации |

Полные правила BAR Lua, все варианты OpenRA GPS/ботов, вся логика Generals shroud/оружия и текущая версия 0 A.D. здесь не проверены. Это не ограничивает выводы по прослеженным функциям, но не позволяет описывать ими всё поведение игр.
