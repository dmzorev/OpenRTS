# 010. Доступная цель, RTS-ввод и исполнение приказов

4 ноября 2026 года. Статус: реализовано. [Исследование трёх референсов](../research/rts-orders-and-controls/README.md), [проверки и кадры](../verification/011-orders-and-controls.md).

## Разделение ответственности

Мышь, клавиатура и кнопки работают с локальным выбором/режимом наведения. Результат — `UnitAction`: вид действия, неизменяемый EntitySet адресатов, мировая точка или EntityId цели и Queued. `SimulationSession.Issue` переводит его в WorldCommand и ставит в тот же журнал, который используется сценариями. Программному источнику не нужно имитировать A или клик.

В Core нет экранных координат, состояния клавиш или курсора. Выбор/рамка/контрольные группы не входят в хеш мира. Пример вызова:

```csharp
using OpenRTS.Core;
using OpenRTS.Core.Orders;

session.Issue(new UnitAction(UnitActionKind.AttackMove,
    new EntitySet([new EntityId(1), new EntityId(2)]),
    new WorldPosition(26 * 1024, 18 * 1024), Queued: true));
```

У ввода три логических состояния: обычное, выбор рамкой, назначение цели. A/M и кнопки включают назначение, ЛКМ подтверждает, Esc/ПКМ отменяет. Начало нового режима отменяет незавершённую рамку. Это небольшой FSM конкретных переходов, без общего движка состояний.

## Коррекция места назначения

DestinationResolver хранит компоненты статической проходимости конкретного Locomotor. Если исходная точка разрешает остановку, геометрически подходит телу и достижима из текущей компоненты, она сохраняется точно. Иначе ищется ближайшая проверенная точка остановки в доступной компоненте: клик танком в воду превращается в подъезд к берегу своей стороны.

Текущая физическая геометрия — полные samples с консервативным расширением препятствий. В каждом sample проверяются комбинации ближайших координат, координат с clearance и центра; лучшая цена — квадрат расстояния до клика, затем Y/X для стабильной ничьей. Это ближайшая точка **среди этих геометрически проверенных кандидатов**, без доказательства непрерывного геометрического оптимума. Отступ у препятствия имеет запас одну fixed-point единицу. В N2 можно заменить геометрию, сохранив смысл действия.

Мобильная занятость не меняет статическую достижимость. Кэш скорректированных точек ограничен 128 запросами на профиль/компоненту; при новой карте создаётся новый resolver. Эти данные производные и не хешируются. Первый поиск недоступной цели пока сканирует samples карты; это ограничение для N4, особенно при множестве разных недоступных целей. Полный поиск ближайшей точки не вызывается при каждом движении курсора: preview использует те же CanStop/CanReach и флаг наличия stop terrain в компоненте. Авторитетная коррекция выполняется при принятии/запуске приказа.

Для группы сначала ищется общая доступная остановка и компактные места. Если общей компоненты/зоны нет, набор разделяется по Locomotor и связной компоненте, и каждая часть получает ближайшую область своей стороны. Это fallback обычного Move, не готовые режимы Together/Dispersed. При отсутствии достаточного места возможен NoRoute; корректировка не создаёт проходимость. Событие DestinationAdjusted сообщает фактическую точку.

Queued-приказы проверяются при запуске: карта или цель могли измениться. Для queued группы сохраняются индивидуальные смещения компактной зоны вокруг исходного клика; это не сохранение начальной формации. При активации каждый waypoint повторно проходит resolver. Самостоятельные пакеты имеют Cohort ID: локальный обмен конечных мест разрешён только внутри одного пакета и одного владельца.

## Активный приказ и очередь

На сущность приходится компактный активный UnitOrder, фаза и FIFO не более 32 приказов. Реализованы Move, AttackMove, Attack, Stop, HoldPosition. Новый обычный приказ заменяет активный и очищает очередь **после успешной проверки**; Queued добавляет в конец. Невалидная замена не удаляет прежнюю очередь. Исчезнувший target при запуске очереди отклоняется, затем проверяется следующий элемент.

Stop прекращает движение/преследование и очередь; на transit-only участке сначала выбирается легальная остановка. Idle после Stop может стрелять по противнику в радиусе, как классический RTS Stop. HoldPosition остаётся постоянным приказом без преследования; queued действия за ним ждут новой замены. Вынужденное физическое ожидание или пауза всё равно могут остановить юнит на transit-only — CanStop ограничивает выбранную цель, не разрешает проход через стену.

Полный Behavior Tree или граф Activities пока не нужен. При многофазной способности, сборе ресурса/возврате груза или сложном строительстве стоит повторно оценить иерархию поддействий, а не добавлять десятки независимых bool.

## Минимальный настоящий бой

Чтобы A-клик имел игровое поведение, добавлен необязательный WeaponDefinition: Range, AcquireRange, Damage, WindupTicks, CooldownTicks. Значения объявляет контент. Это hitscan-прототип: без снарядов, брони, AoE и сложных способностей.

AttackMove хранит исходный waypoint независимо от временной цели: обнаруживает врага, подходит на дистанцию, стреляет, после потери/уничтожения цели возвращается к waypoint. Обычный Move не переключается на бой. Attack явно преследует EntityId. Idle/Hold ищут только в радиусе оружия и не преследуют.

Поиск целей использует spatial buckets MotionIndex, ограниченный радиус и стабильную ничью distance/EntityId; это не полный перебор пар. Периодическая acquisition распределена по ID на четыре тика. LoS проверяется по статической маске препятствий с радиусом ноль; разные права прохода по воде/лесу сами по себе не являются маской для выстрела. При выборе сразу фильтруются невидимые цели, чтобы скрытый ближайший враг не подавлял видимого.

В демонстрации одинаковый Owner — союзник, разные ненулевые — противники, ноль — нейтральный. Уступание в карман и обмен групповых мест не заставляют чужого владельца отходить. Полной системы отношений/дипломатии и права клиента на управление в Core ещё нет; полигон разрешает управление только Owner=1, остальных можно осматривать.

Move до fire отменяет windup. Cooldown после выстрела сохраняется при смене приказа; он ограничивает начало следующего windup, длительность подготовки задаётся отдельно. Пауза/темп не меняют число тиков. Все выстрелы тика вычисляются до удаления погибших, урон агрегируется/применяется по EntityId. Поэтому одновременный смертельный залп допускает ответный выстрел обеих сторон. Packed removal не меняет выбор цели и результат. WeaponFired содержит target/clip/duration, Damaged — фактический урон; события не зависят от пропуска кадров.

Нет обещания полного оптимального поиска позиции для стрельбы: явный Attack может ждать у ближайшей достижимой границы, если цель остаётся вне радиуса/LoS. Это отдельная дальнейшая задача политики приказа.

## Курсоры и структура

RtsOverlay рисует анимированные векторные курсоры и рамку поверх CanvasLayer. Они не привязаны к игровым тикам и продолжают анимацию при паузе. Курсоры различают выбор/осмотр, движение, коррекцию берега, атаку и недоступность. Формы отличаются кроме цвета. Native AnimatedTexture cursor не используется: Godot показывает у него только первый кадр; ограничение подтверждено в исследовании. Кнопки HUD принимают события через GUI, активная рамка получает release через _Input, обычные команды — через _UnhandledInput.

Код сгруппирован без новых assemblies:

| Каталог | Назначение / namespace |
| --- | --- |
| Core/Simulation | Мир и его partial-фазы; фасад OpenRTS.Core |
| Core/Navigation | Грунт, resolver, поля, геометрия, broad phase; OpenRTS.Core.Navigation |
| Core/Orders | UnitAction, команды, очередь и обработка; OpenRTS.Core.Orders |
| Core/Combat | WeaponDefinition и исполнение выстрелов; OpenRTS.Core.Combat |
| Core/Presentation | Публикуемые позы/анимации; OpenRTS.Core.Presentation |
| Core/Hosting | Session/FrameExchange; фасад OpenRTS.Core |
| Content/Catalogs, Scenarios | Загрузчики отдельно от сценариев; сценарии OpenRTS.Content.Scenarios |
| Godot/Rendering, Controls | Пакетное отображение отдельно от локального ввода |
| sandbox/Controls, Verification | Управление полигона и проверки; Sandbox.cs остаётся точкой входа сцены |

Partial-файлы SimulationWorld остаются одним типом OpenRTS.Core, независимо от каталога. GlobalUsings проектов явно связывают подпространства. Локальные потребители обновлены; импорт MIT-библиотеки DeclarativeContent не менялся. Версии: direct hash 4, navigation hash 8, UnitCatalog fingerprint 4.
