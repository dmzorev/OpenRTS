# 009. N1: грунт, Locomotor и цена маршрута

Дата: 4 ноября 2026 года. Статус: реализовано. Продолжает [N0](006-exact-movement.md) и [план навигационных слоёв](../research/navigation-layers/roadmap.md).

## Данные и границы

NavigationGrid хранит независимые неизменяемые terrain IDs (byte, до 256 типов) и прежнюю маску статических препятствий. BlockCell/UnblockCell меняют маску с новой ревизией, сохраняя terrain. Юнит получает типизированный Locomotor с плотной таблицей TerrainRule; YAML и имена грунтов в исполнении Core не нужны.

TerrainRule разделяет:

- `Traverse`: физический проход с текущим радиусом тела.
- `CanStop`: разрешение конечной цели, начального положения, Spawn и кармана уступания. Не превращает участок в стену.
- `Speed`: множитель скорости 1..1024, где 1024 — полная World.SpeedPerTick.
- `Cost`: независимую положительную цену единицы расстояния 1..65536. Для непроходимого типа CanStop=false, Speed=Cost=0.

Профиль содержит хотя бы один проходимый тип. Его правила и таблица карты проверяются до создания мира. Публичные запросы также проверяют индексы/покрытие типов. На полигоне `terrain.yaml` объявляет семь грунтов и три Locomotor; `Movement.Locomotor` в units.yaml связывает их с юнитом. Ровно один Default грунт получает индекс 0; остальные сортируются ordinal. Каждый профиль обязан объявить все типы. UnitCatalog fingerprint формата 3 включает порядок типов и реально связанные правила, но по-прежнему исключает Model/спрайты.

Миры без terrain IDs, у которых все правила для типа 0 равны обычному грунту, сохраняют быстрый бинарный GridNavigator и прежнее групповое дерево. Реальный второй алгоритм — WeightedNavigator, без заранее созданного универсального интерфейса.

## Маршрут и связность

Для точечных приказов WeightedNavigator строит общие обратные поля Dijkstra. Ключ — `(Locomotor, goal)`, плюс текущая неизменяемая карта. Цена кардинального ребра — сумма Cost двух клеток: это удвоенная цена от центра до центра без общего множителя CellSize. Long сохраняет значения выше Int32; пределы карты и Cost оставляют запас от переполнения.

Соседи и равные приоритеты имеют стабильный порядок. Число построенных полей за тик ограничено; запросы отсортированы, обслуживание вращается, замещение FIFO. Параллельны независимые поля; публикация идёт в порядке запросов. Незавершённый результат после отмены не публикуется. Последовательный и обратный параллельный порядок проверены одинаковыми хешами мира.

Связные компоненты по Traverse строятся лениво на профиль и ревизию. Мобильные соседи в них не входят. CanStop не разрывает связность. Компоненты — производные данные, не очередь игровых результатов. Для N1 совместный предел `cells × profiles <= 16 Mi` ограничивает labels до 64 MiB. Поля занимают до 128 MiB; профилей в активном weighted мире не больше 16. Это подробная сетка, не иерархия N4.

Группа использует отдельное общее взвешенное дерево на Locomotor, а не глобальный поиск на каждого участника. Родители выбираются Dijkstra; лес содержит все проходимые компоненты. Путь между назначенными местами по этому дереву остаётся приближённым, как прежний SharedRouteTree. Оптимальность гарантируется для цены точечного поля в его четырёхсвязном графе, не для группового дерева или итогового any-angle пути.

## Произвольные отрезки и движение

Геометрическая проверка отрезка учитывает запрещённые профилю типы как препятствия, включая радиус. Цена отрезка считается отдельно по длине пересечения centerline с каждым terrain sample. Q32-параметры пересечений и Int128-промежуточные суммы исключают float в игровых решениях. Поэтому визуальный круг эффекта по-прежнему не становится клеточным шаблоном: эффекты сюда не добавлялись.

Прямой путь без построения поля допустим, когда он достигает нижней границы цены по минимальному Cost профиля. Сглаживание рассчитанного пути допускает дальний поворот только если его отрезок не дороже заменяемой части маршрута. Иначе короткий срез мог бы отменить объезд дорогого болота. Локальное ограниченное исследование тоже расширяет выборки по цене профиля; его окно/глубина по-прежнему не гарантируют разрешение любого затора.

Скорость выбирается по типу под центром в начале тика. Остаток деления на 1024 хранится в сущности и входит в хеш; например Speed=1 при базовом шаге 128 даёт единицу перемещения каждые восемь тиков. На границе покрытия применяется дискретизация одного тика, а не точное интегрирование времени внутри отрезка. Cost можно настроить независимо; в демонстрации он примерно обратно пропорционален Speed, без обещания оптимума по фактическому времени прибытия.

Пакет одинакового сдвига N0 отключён для weighted мира: разные покрытия/профили могут дать разный шаг. Swept-проверки и локальная занятость сохранены. Радиус пока общий, 256; частичная геометрия, уклоны и разные размеры относятся к N2.

## Остановка и группы

Недопустимый Move возвращает NoRoute и сохраняет прежний допустимый приказ. Это важно на transit-only участке: клик по текущей позиции не должен отменять переход. Spawn там отклоняется. Вынужденное ожидание перед телом или остановка паузы всё равно возможны: CanStop ограничивает выбор назначения, а не разрешает продавливаться через препятствие.

Для MoveGroup места должны подходить всем присутствующим профилям. При несовместимой точке приказ отклоняется целиком. Каждый участник затем идёт по своему профилю и со своей скоростью; общего темпа Together или автоматического разбиения Dispersed нет до N6. Ни формация, ни исходные offsets не сохраняются.

Хеши: direct 3, navigation 7. Включены правила Locomotor, terrain IDs, дробный остаток и состояние weighted cache. Производные компоненты, временные затраты и workers исключены. Старые отчёты остаются историческими.
