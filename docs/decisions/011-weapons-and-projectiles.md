# 011. Оружие, установленные орудия и летящие снаряды

Дата: 2026-11-04. Статус: реализовано. Заменяет минимальный hitscan-контракт из решения 010. [Исследование референсов](../research/weapons-and-projectiles/README.md).

## Границы

Core получает неизменяемые `WeaponDefinition` и `WeaponMountDefinition`, броню и возможность движения юнита. Ни имён игровых юнитов, ни Godot-ресурсов, ни YAML в Core нет. `WeaponCatalog` загружает именованные определения; `UnitCatalog` связывает их с именованными mounts, анимациями и `FireWhileMoving`. Конкретный баланс — `sandbox/content/weapons.yaml` и `units.yaml`.

Модели и эффекты загружаются отдельно. `ModelPart.Mount` связывает направление детали с орудием; семантическая анимация mount выбирает клип модели. `effects.yaml` описывает цвет/размер снаряда, трассера, попадания и длительность визуального эффекта. Эти данные, ресурсы и палитры не входят в gameplay fingerprint. Броня пока — три общих класса `Living`, `Mechanical`, `Building`; расширяемый реестр материалов не создавался.

Все тестовые сценарии перенесены из Content в `sandbox/Scenarios`, namespace `OpenRTS.Samples`. Headless и проверки явно подключают эти исходники как fixtures. Godot `TerrainView` получает раскладку/ресурсы от клиента, `SpriteWorldView` — палитру владельцев; адаптер больше не ссылается на ShowcaseScenario и не задаёт цвета команд игры.

## Время и выбор цели

Каждое орудие хранит собственные `ReadyTick`, `FireAtTick`, `ChargingTarget`, `BurstRemaining`, цель, направление и playback. Первому выстрелу серии предшествует windup; затем следуют `BurstIntervalTicks`; после последнего выстрела начинается `CooldownTicks` (YAML: `ReloadTicks`). Следующая серия снова имеет windup. Смена приказа отменяет подготовку, но сохраняет оставшиеся выстрелы и срок следующего разрешённого выстрела. Перенацеливание не пополняет серию и не обнуляет перезарядку.

Явные Attack/Repair используют цель приказа; для сближения выбирается подходящее оружие с наименьшей дальностью. Это позволяет подвести юнит с разными дальностями так, чтобы могли работать оба орудия. Орудия независимо проверяют дальность, LoS, класс цели и разрешение на стрельбу в движении. При отсутствии подходящей основной цели боевые орудия могут выбирать свою ближайшую цель. Поиск пространственный, проверки нового захвата распределены по четырём тикам; ничья разрешается по EntityId. Это простая стратегия, без оценки угроз и оптимального распределения огня.

Обычный Move сохраняет движение; `FireWhileMoving` разрешает орудию захват и выстрелы параллельно ему. Пешие орудия по умолчанию при движении не стреляют. AttackMove и явная атака останавливаются на дистанции поражения; режим сохранения скорости для целой группы не вводился.

Repair — отдельный `UnitAction`/`CommandKind`, который может поступить через Session.Issue, UI или программно. Только другой юнит того же ненулевого Owner, с неполным HP и ненулевым модификатором ремонта. В sandbox ремонт действует на технику/здания, не на живых. Enemy/neutral/self/full-health не допускаются Core. При полном HP или исчезновении цели приказ завершается. Полная дипломатия пока не реализована.

## Способы доставки

| Тип | Поведение |
| --- | --- |
| Hitscan | Воздействие в текущем тике; в sandbox автомат с burst и ремонтный луч |
| Cannon | Фиксирует точку при запуске; цель может уйти с линии, другой допустимый объект может перехватить снаряд |
| Missile | Каждый тик направляется к текущему положению цели; скорость ограничена, суммарный пройденный путь расходует TravelLimit |
| Grenade | Летит к фиксированной точке, не сталкивается с телами до приземления; наносит круговой AoE. Высота дуги — данные представления, не трёхмерная баллистика |

Снаряд — отдельное состояние мира, живёт после удаления стрелка. Исчезновение цели гасит homing-ракету; обычный снаряд продолжает полёт. Все летящие типы ограничены TravelLimit. Длина каждого шага округляется вверх при расходе запаса дальности. Ракета меняет курс сразу; инерции и ограничения угловой скорости пока нет.

Broad phase использует MotionIndex и начальные позиции тел с padding на максимальный шаг. Narrow phase проверяет относительное движение снаряда и тела на всём интервале тика, Int128 и доли 1/65536. Выбирается первое пересечение, при равном времени — меньший ID. Телам пока соответствует общий радиус 256. Статическая blocked-маска останавливает снаряды; точка эффекта на таком столкновении пока берётся в начале заблокированного сегмента, без точного вычисления точки входа в стену.

AoE — круг в мировых координатах, проверяется по центрам целей через пространственных кандидатов. Сейчас равномерный эффект без falloff/укрытий/экранирования стенами. По умолчанию союзники не получают splash; `FriendlyFire` явно включает collateral, в том числе собственный урон. Приказы Damage всё равно требуют врага. Проходимость Locomotor не делает воду или лес пуленепробиваемыми: LoS и снаряды используют static mask.

## Воздействие и детерминизм

Сменный приоритет автоматического выбора цели в Gameplay описан в [решении 029](029-combat-target-priority.md).

Модификатор брони — целый процент 0..1000; `floor(Damage * Modifier / 100)`, без скрытого минимального урона. Ноль запрещает прямой выбор такой цели этим оружием. Процент меняет урон/ремонт, а отношение к владельцу проверяется отдельно. Урон и лечение всех выстрелов/попаданий агрегируются за тик; применяется сначала урон, затем лечение выжившим, с clamp к MaxHealth. Летальный урон нельзя отменить ремонтом. Погибшие удаляются по ID после обработки всех орудий, поэтому возможен ответный выстрел в одном тике.

Порядок фаз: приказы → движение → орудия/новые запуски → продвижение ранее запущенных снарядов → накопленные воздействия/смерти → семантическое представление. Новый снаряд начинает полёт со следующего тика. Порядок обхода орудий — EntityId, затем порядок mount из определения (для YAML — ordinal имя); снаряды — монотонный ID. Floats и часы Godot не участвуют в результате.

Состояние mounts, частичная серия, подготовка, очередь и монотонные ID/состояния снарядов входят в хеш. Форматы теперь **direct 5 / navigation 9 / UnitCatalog 5**. Отчёты предыдущих этапов — исторические, их хеши не сравниваются с этим этапом. Derived spatial buckets исключены. Отмена шага оставляет мир незавершённым; позы оружия и снарядов, как и EntityPose, не публикуются.

## Представление и неподвижность

FrameExchange публикует три закреплённых массива: EntityPose, WeaponPose, ProjectilePose. `EntityPose.WeaponOffset/WeaponCount` адресуют каналы того же слота; их нельзя использовать со span другого кадра. Жизнь span ограничена FrameLease. Packed removal не меняет уже закреплённый слот. События WeaponFired/ProjectileImpact/Expired/Repaired передаются отдельно от кадров, с mount/target/позицией/ID снаряда.

Godot рисует снаряды, трассеры и попадания тремя MultiMesh, без узла на каждый выстрел. Составная модель может привязать разные части к разным mounts. Для одной общей детали одновременно учитываются импульсы recoil/flash всех подходящих каналов; базовый SpriteFrames-клип выбирается последним активным подходящим каналом, это не skeletal animation mixer. У комбинированной башни общий поворот берётся от `main`, а пушка и ракеты имеют независимые вспышки/перезарядку.

`UnitDefinition.Movable=false` запрещает Move/AttackMove и уступание. В смешанном групповом приказе неподходящие получатели получают InvalidOrder, остальные продолжают. Attack не пытается двигать неподвижный объект к далёкой цели. ДОТы пока остаются обычными круговыми телами и не создают многоклеточную маску здания. Навигационные статусы footprint — следующий отдельный этап.

## Проверки и пределы

[Верификация](../verification/012-weapons-and-projectiles.md): YAML/ссылки, burst, dodge, swept crossing/interception, fuel, исчезновение участников, броня/AoE/friendly fire, ally-only ремонт, одновременный летальный урон, два оружия на ходу, неподвижность, frame leases и workers. Измерены отдельные 10000 стрелков и 10000 летящих ракет; это не доказательство пропускной способности плотного боя с навигацией.

Текущие защитные лимиты: до 8 mounts на тип, дальность выстрела 512..8192, захват <=12288, SplashRadius <=8192, скорость снаряда 1..4096, TravelLimit от Range до 65536, серия <=64. Единицы мира — 1024 на world unit. Для артиллерии с большими дальностями потребуется пересмотреть бюджеты spatial-запросов вместе с этими пределами.

## Пример объявления

```yaml
# weapons.yaml — игровая семантика, Core получает подготовленный WeaponDefinition
cannon:
  Weapon:
    Projectile: Cannon
    Range: 6144
    AcquireRange: 8192
    Speed: 448
    Damage: 70
    ReloadTicks: 38
    WindupTicks: 3
    Versus: {Living: 10, Mechanical: 150, Building: 90}

# units.yaml — связь без знания конкретной текстуры/рига
my-unit:
  Health: {HP: 400, Armor: Mechanical}
  Presentation: {Model: my-model, Animations: [idle, move, fire]}
  Armaments:
    Mounts:
      main: {Weapon: cannon, Animation: fire, FireWhileMoving: true}
```

Загрузчик получает отдельные источники: `WeaponCatalog.Load(...)`, затем `UnitCatalog.Load(unitSources, locomotion, weapons)`. Model/Effect каталоги загружает только визуальный потребитель. При наличии Movement.Locomotor нужен соответствующий LocomotionCatalog. `Model: my-model` в примере должен быть объявлен в modelSources; его часть с `Facing: Weapon, Mount: main` следует направлению этого орудия.
