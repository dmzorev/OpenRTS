# 035. Корневой манифест и настройки игры

Дата: 15 ноября 2026 года.

`OpenRTS.Content.GameManifest` загружает `game.yaml` версии 1. Манифест содержит `Title`, обязательный список `Rules` и необязательные `Terrain`, `Weapons`, `Models`, `Icons`, `Effects`, `Settings`. Каждый элемент — файл или директория. Это обычный YAML, совместимость с MiniYaml не требуется.

```yaml
Version: 1
Title: My RTS
Rules: [content/rules]
Terrain: [content/terrain.yaml]
Weapons: [content/weapons]
Models: [content/models]
Icons: [assets/icons/game/icons.yaml]
Effects: [content/effects.yaml]
Settings: [content/settings]
```

`Icons` — плоские объявления `Model ID: res://path.png` для готовых текстур панели команд. Это не модели: файл не требует `Parts` и `Animations`. Пути, неизвестные ID и повторы между файлами проверяются при `LoadModels`. Секция необязательна; без неё иконки берутся из корневого `ModelPart`, как раньше. Генерация и ограничения — [053](053-composed-unit-icons.md).

## Загрузка

1. Строго проверить манифест: неизвестные поля, другая версия, anchors/tags/aliases и пустые объявленные списки запрещены.
2. Обработать элементы списка по порядку. Директорию раскрыть рекурсивно; внутри всего её поддерева сортировать полные относительные пути через `StringComparer.Ordinal`. Выбирать `.yaml`/`.yml` без учёта регистра. Директория без YAML — ошибка. Символьные ссылки внутри директорий не обходятся, глубина ограничена 64.
3. Нормализовать разделители, `.` и внутренние `..`. Пути относительны директории манифеста; абсолютные пути в декларациях и выход выше корня запрещены. Один нормализованный путь учитывается один раз в пределах секции. Разные файлы с одинаковым ID остаются ошибкой; last-wins merge не вводится.
4. Передать все источники секции существующему каталогу вместе. Наследование между файлами работает как прежде, fingerprint не зависит от разбиения. Секции независимы: одно имя в Models и Rules допустимо.
5. Ошибка чтения включённого пути указывает место объявления в манифесте. Ошибка контента указывает исходный файл/строку. Несуществующие файлы не пропускаются.

`ContentFiles` отделяет раскрытие путей от чтения. Локальная файловая система и Godot `FileAccess`/`DirAccess` используют один алгоритм. Каталоги получают `ContentSource`; импортированная DeclarativeContent не меняется. В Gameplay/Core нет YAML и файлового I/O. Горячей перезагрузки нет.

## Первые настройки

`Settings` использует `DefinitionSet` и строгий `Options.Bind`. Каждая секция объявляется один раз во всём наборе файлов. Можно держать их вместе либо в отдельных файлах. Необъявленные секции и поля получают совместимые значения по умолчанию. Неизвестные поля и повторное объявление секции дают ошибку.

- `Simulation`: `TickRate` (1..1000, default 25), `SpeedPerTick` (1..1024 world units за тик, 128). Оба хоста передают значения в `MapMatch.CreateWorld`; они уже входят в хеш мира. Частота тика меняет длительность действий в секундах и отличается от PlaybackSpeed.
- `Match`: `DefaultMap`, `DefaultStartSet`, `AiConfig`, `AiProfile`; меню `Maps`/`StartingSets` с `Path`, `Title`, необязательным `Description`. При отсутствии списка меню содержит единственный default. В непустом списке default должен присутствовать. CLI переопределяет выбор. Стартовый набор по умолчанию применяется только к skirmish-карте.
- `SensorRanges` хранит цвета, режимы отображения и правила отображения радиусов по владельцам.
- `Presentation` хранит `Renderer` (`Godot3D`), `Camera` (`Default` или `Isometric`) и `ModelOverrides` (исходный Model ID → альтернативный Model ID). Загрузка проверяет оба ID в `Models`. Замены применяются независимо к исходному каталогу. Рендер матча и предпросмотр Godot используют один подготовленный каталог. Настройки принадлежат представлению и исключены из игровых отпечатков. [Пример мода](../sandbox.md#изометрический-yaml-мод)

Simulation settings относятся к запускам карт. Диагностические direct/navigation/showcase/buildings/fog сценарии сохраняют фиксированные параметры. Match — настройки выбора/UI; пути и подписи не добавляются в gameplay fingerprint. Подготовленные позиции, игроки, кредиты и seed входят в обычное состояние мира. Общий хеш текстов конфигурации не вводится.

## Хосты и совместимость

Sandbox использует `res://game.yaml` для игры со зданиями, `res://diagnostic-game.yaml` для остальных лабораторий. Headless выбирает те же файлы из `sandbox/`. Оба принимают `--mod=path`; Godot также принимает `res://` путь. Явный манифест определяет весь состав каталогов независимо от сценарного флага.

Старый positional `units.yaml` в headless сохранён со старым поиском соседних файлов; одновременно с `--mod` он запрещён. Относительные `--map`/`--start-set` при работе с манифестом разрешаются от его корня; абсолютные CLI-пути поддерживаются. Явный headless `--ai-config` сохраняет разрешение от рабочего каталога, default `AiConfig` — от корня манифеста.

Существующие файлы контента не перемещены. Подкаталоги rules проверяются временным набором с наследованием. `Settings: [content/settings]` демонстрирует директорию на реальном контенте.

[План остальных настроек](../research/game-configuration/README.md) отделяет предложения от реализованного контракта. Дополнительные поля требуют реального типизированного потребителя, валидации и проверки воспроизводимости. Алгоритмические пределы не становятся параметрами YAML автоматически.
