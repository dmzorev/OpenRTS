# 031. Трансформация акторов

Игра регистрирует именованные переходы в `GameplayMechanics.Transformations`. Исходный и целевой типы берутся из того же каталога, который получает `SimulationWorld`. Поддерживаются переходы между подвижными и неподвижными формами в обе стороны. Каждый успешный переход создаёт новый `EntityId` и сохраняет владельца и долю здоровья с округлением вниз и минимумом 1 HP. За состояниями, привязанными к старому ID, действуют обычные правила удаления. Превращение доступно для живого актора на карте без пассажиров, груза, активного проекта апгрейда и задач производства.

```csharp
var mechanics = new GameplayMechanics
{
    Transformations =
    [
        new("deploy", "mcv", "construction-yard", After: new("unfold", 18)),
        new("pack", "construction-yard", "mcv", Before: new("fold", 18))
    ]
};

// Ссылки на клипы должны существовать в Animations соответствующих типов.
session.Transform(mcv, "deploy", site);
session.Transform(yard, "pack", destination);
session.Transform(mcv, "deploy"); // Развернуть в текущем месте.
```

У `CommandKind.Transform` те же параметры. Команда принимает один ID и имя действия. `TransformHere` использует текущую позицию. Если подвижный актор становится зданием, переданная точка задаёт выровненный центр будущего footprint. Для `TransformHere` центр выравнивается по ближайшей допустимой линии сетки с учётом размеров и границ карты. Из здания в подвижную форму точка задаёт последующий Move. Здание в здание меняет форму на месте с выравниванием нового footprint. Поворот footprint разрешается для отдельного перехода через `AllowRotation` и задаётся в четвертях оборота. Игра может отправлять те же переходы из `GameplayTick.TryTransform`, например из правила, которое видит событие завершения апгрейда.

## Площадка и фазы

1. В пути `EntityPose.Transformation` публикует будущий тип, центр, ориентацию и фазу. По этим данным хост рисует план. Площадка открыта для движения и обычной стройки. Если появившийся объект перекроет footprint или изменится допустимость грунта, план отменяется.
2. При подходе к границе площадки движок проверяет тела. Союзникам того же владельца и нейтралам назначается движение к свободному выходу, чтобы в том числе освободить точный центр. Враг или неподвижное препятствие отменяет план. При отсутствии продвижения или затянувшемся освобождении действует предел 250 тиков. Успешный новый приказ без очереди отменяет подход.
3. После прибытия `Before` может запустить клип на исходном акторе, а после замены `After` может запустить клип на новом. Каждый клип задаёт длительность в тиках и, при необходимости, направление. В обеих фазах актор уязвим и временно имеет условие `Constructing`. Приказы, оружие, производство и участие в экономике приостановлены. Если площадка снова занята в фазе подготовки, план отменяется.
4. Замена выполняется после движения и боя. Мир готовит новую карту с удалённым старым footprint и добавленным новым, проверяет остальных акторов и применяет итоговую ревизию. Подвижная форма после свёртывания проверяет возможность остановки и отсутствие перекрытий в центре исходного здания. При отказе исходный актор сохраняется. При успехе `ActorTransformed.Entity` указывает старый ID, `TargetEntity` новый. Хост может перенести выделение по этому событию.
5. После `After` переход завершён, актор снова принимает приказы, а отложенный Move передаётся новой подвижной форме. `TransformationCompleted` и `TransformationCancelled` позволяют хосту обновить обратную связь. Очереди приказов, выдачи условий, цели боя и сторонние ссылки автоматически не перенаправляются.

Проекты обрабатываются в порядке ID. Рецепты и незавершённые переходы входят в отчёт симуляции. Событие замены публикуется без события смерти и без руин.
