# 025. Подключаемый захват и правило конца тика

Дата: 7 ноября 2026 года. Реализован срез [плана границ механик](../research/mechanic-modularity/README.md).

## Сборка мира

`SimulationWorld.CreateWithMechanics` принимает `GameplayMechanics`. `Capture` по умолчанию использует встроенный захват. Игра может передать свою `GameplayRegistration<ICaptureMechanic>` с ID, версией и фабрикой экземпляра на мир. Явное `Capture = null` отключает слот. Мир проверяет зависимые definitions до создания сущностей. Старые конструкторы, команды, YAML и поля прогресса в кадре сохраняют свои точки входа.

```csharp
var mechanics = new GameplayMechanics
{
    Capture = new("my-game.breach-capture", 1, () => new BreachCapture()),
    EndOfTick = new("my-game.hold-score", 1, () => new HoldScore(objective))
};
using var world = SimulationWorld.CreateWithMechanics(mechanics, unitTypes, width, depth);
```

`EndOfTick` принимает отдельное правило. Оно получает тик и читает владельцев живых сущностей по `EntityId` после движения, боя, стройки и производства. Пример правила начисляет очко текущему владельцу цели и держит счёт в собственном экземпляре. Потребитель может опубликовать этот счёт через адаптер своей игры.

## Граница захвата

- Механика определяет допустимость захвата, состояние своих ECS-компонентов, переход между приближением, выполнением и завершением, а также поля прогресса. `UseAbility` и `CaptureTarget` используют тот же механизм активных и отложенных приказов.
- Система проверяет существование цели, принадлежность разным владельцам и отсутствие пассажиров в цели. Мир выполняет движение и смену владельца, очищает прежнюю производственную очередь, возвращает неиспользованную оплату её плательщику, переносит энергию и публикует `OwnerChanged`.
- Экземпляр принадлежит одному миру и выполняется на его потоке. `Initialize` может добавить собственные компоненты. Проверка `CanStart` читает состояние, а `Advance`, `Reset` и `OwnerChanged` меняют существующие компоненты механики. Frent handles в этом API имеют область жизни симуляции. Структурные изменения при исполнении приказа могут инвалидировать refs общих компонентов.
- Для пользовательских механик отчёт использует форматы 17 и 18. Он включает ID, версию, канонические данные экземпляра и вклад Capture для сущностей по возрастающему ID. Колбэки записи читают состояние и записывают данные с однозначными границами. Стандартные миры сохраняют форматы 10 и 14, а миры со сменным темпом производства без других пользовательских механик — 15 и 16.

## Композиция системы

`SimulationWorld` собирает `CaptureSystem` через слот `GameplayMechanics.Capture`. Система владеет допуском цели, обработкой способности и активного приказа, вызовами исполнителя, проекцией прогресса и записью состояния. `ICaptureWorld` предоставляет чтение живых сущностей и definitions, проверку груза и синхронные операции принятия приказа, движения и смены владельца. Изменяющие операции принимают `EntityId`. Поиск индексов ECS выполняет координатор. [Система и контракт](../../src/OpenRTS.Gameplay/Capture/CaptureSystem.cs) · [Подключение мира](../../src/OpenRTS.Gameplay/Simulation/SimulationWorld.cs)

Orders вызывает систему в существующем проходе активных приказов. Общая очередь и смена владельца обслуживают все механики. Слот создаёт систему для зависимого каталога либо явно зарегистрированного исполнителя. При отсутствующей системе её вклад в отчёт использует две пустые записи исходного формата.

При сравнении с `d1a8945` в отдельном приложении совпали события, прогресс кадра и хеш каждого тика для обоих входов команды, встроенного и сменного захвата. Четыре headless-отчёта совпали побайтово для прямого движения, навигации с обратным порядком задач и skirmish на 1 и 4 workers. Из Release прошли 226 проверок OpenRTS и 20 проверок DeclarativeContent.

## Сценарий проверки

Реализация из сборки игры хранит собственный компонент прогресса и сокращает требуемый прогресс, если цель получила урон до половины HP. Правило счёта подключается отдельно. Сценарий проверяет оба входа, очередность после `Move`, прогресс в кадре, владение, возврат 14 кредитов из предоплаты, энергобаланс, счёт в тик захвата и удаление цели. Миры на 1 и 4 workers сравниваются по событиям и хешам. Отдельная проверка отключает Capture и проверяет раннее отклонение зависимого каталога. [Сценарий](../../tests/OpenRTS.Tests/CaptureMechanicChecks.cs)

Прошли 221 проверка OpenRTS в Release и 20 проверок DeclarativeContent в Debug. Шесть headless-отчётов совпали побайтово с результатами до выделения Capture. Сквозные проверки Godot прошли с локальным фильтром сообщения о недоступном хранилище сертификатов macOS при запуске движка в песочнице.

Синхронный старт восьми сессий воспроизвёл сбой Frent и на предыдущей сборке. Core сериализует структурные операции и время жизни запросов Frent между мирами. Закрытие запроса может запустить буфер структурных команд, поэтому защита охватывает и этот шаг. После изменения прошли 60 повторов сценария с восемью сессиями. Навигационные задачи выполняются вне этой блокировки. Пропускная способность нескольких миров отдельно не измерялась.
