# 029. Сменный приоритет цели в Combat

Дата 7 ноября 2026 года. Этап [плана границ механик](../research/mechanic-modularity/README.md).

## Граница правила

При автоматическом поиске Combat выбирает кандидатов через пространственный индекс и проверяет отношение владельцев, совместимость оружия, дальность и линию огня. `ICombatTargetRule` получает данные прошедшего эти проверки кандидата и контекст поиска. При стрельбе из транспорта контекст содержит носитель как физический источник и определение оружия пассажира. [Контракт](../../src/OpenRTS.Gameplay/Combat/ICombatTargetRule.cs) · [Автоматический поиск](../../src/OpenRTS.Gameplay/Combat/SimulationWorld.Combat.cs#L62)

Большая оценка имеет приоритет. `null` пропускает кандидата. При равных оценках выбирается ближайшая физическая граница, затем меньший `EntityId`. Штатный поиск использует одинаковую оценку для всех кандидатов. Правило читает входные данные и неизменяемую конфигурацию. Порядок вызовов определяется пространственным индексом и может различаться между запусками.

Поиск новой цели вызывают `AttackMove`, установки с автоматической стрельбой и автоприменение ремонта. Удержание действующей цели, явные приказы атаки и ремонта и ручные способности проходят прежнюю проверку допустимости. Combat управляет выбором установки, подготовкой, снарядами, применением урона и смертью в прежних фазах.

## Регистрация и хеш

```csharp
var mechanics = new GameplayMechanics
{
    CombatTargeting = new("game.health-priority", 1, static () => new HealthPriority())
};
using var world = SimulationWorld.CreateWithMechanics(mechanics, unitTypes, width, depth);
```

Фабрика создаёт правило для мира. Заголовок формата 22 содержит ID и версию регистрации, затем конфигурацию из `WriteConfiguration` и существующий блок механик. Так в хеше сохраняются и другие зарегистрированные механики. Штатные миры сохраняют прежние форматы. [Регистрация и запись](../../src/OpenRTS.Gameplay/Simulation/GameplayMechanics.cs#L48)

## Проверки

Правило из отдельной сборки игры предпочитает раненого противника в `AttackMove` и при стрельбе на ходу. Проверены равенство оценок, исключение недопустимых кандидатов, сохранение текущей цели при появлении более приоритетной и возможность атаковать явно цель, которую правило пропускает. Сравниваются события и хеши на 1 и 4 workers. [Сценарии регистрации](../../tests/OpenRTS.Tests/CombatTargetRuleChecks.cs)

До и после изменения штатного поиска совпали 6969 снимков по тикам, включая хеши, события, приказы, здоровье и состояние орудий. Совпали итоговые отчёты шести headless-прогонов. Прошли 230 проверок OpenRTS, 20 проверок DeclarativeContent и сквозная проверка Godot.

В раздельных Release-прогонах с 10 000 стрелков и 10 000 летящих ракет совпали объём работы и итоговые хеши. Аллокации потока симуляции составили 0 байт за 16 измеряемых тиков в каждом прогоне. [Параметры нагрузки](../verification/012-weapons-and-projectiles.md#раздельные-измерения)
