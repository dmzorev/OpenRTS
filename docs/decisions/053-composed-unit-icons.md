# 053. Составные иконки юнитов

Дата: 24 ноября 2026 года.

Иконка панели команд раньше брала кадр корневого `ModelPart` из `SpriteFrames`. У разных юнитов совпадают корпуса, поэтому иконки не различали турели, радары, ракеты и другие установленные части. Составная иконка собирается из того же `ModelCatalog` и `SpriteWorldView`, что и игровая модель, но снимается один раз офлайн.

## Данные

`ModelDefinition` получает необязательный `Icon` — путь `res://` к готовой текстуре. Это адаптерное поле: оно не входит в `UnitCatalog` и игровые отпечатки, симуляция его не читает.

Иконки объявляются отдельной секцией манифеста, а не повторным `Model` с тем же ID: `DefinitionSet` запрещает повторные определения. Секция `Icons` содержит файлы или директории; каждый файл — плоское отображение `Model ID: res://path.png`. Файл не является самостоятельной моделью, поэтому не требует `Parts` и `Animations`.

```yaml
Icons:
  - assets/icons/isometric-game/icons.yaml
```

Пути проверяются при загрузке: только `res://`, только конкретные Model ID, без повторов между файлами, неизвестный ID — ошибка с источником. Объявление применяется к базовому каталогу моделей, затем `Presentation.ModelOverrides` копирует иконку заменяющей модели на исходный ID. Если иконка явно задана и для исходного ID, после замены она сохраняется. В стандартном профиле без секции `Icons` поведение прежнее.

## Генерация

`tools/build_unit_icons.py` — Python-обёртка над `sandbox/IconBuilder.tscn`:

```sh
python3 tools/build_unit_icons.py sandbox/isometric-game.yaml --vehicles --install
```

- Аргумент — `game.yaml` или `isometric-game.yaml`; режим камеры берётся из `Presentation.Camera`.
- `--id` (повторяемый) выбирает юнит или Model ID; `--vehicles` оставляет подвижные юниты с бронёй Light/Mechanical, включая авиацию.
- `SandboxIconBuilder` итерирует `UnitCatalog.Presentations`, применяет `ModelOverrides`, пропускает повторно встреченные модели и рендерит позу `North` с idle-анимацией. Используется тот же `SpriteWorldView`, поэтому слои, `FarLayer`, направления, пивоты и team-маркеры совпадают с игрой.
- Первый проход с широкой ортокамерой находит видимые пиксели, второй центрирует модель и подгоняет её под 86% кадра; результат уменьшается Lanczos до `--size` (32..2048, по умолчанию 256).
- Выход — `sandbox/assets/icons/<game>/`: PNG, `icons.yaml` и `index.json`. Полная сборка заменяет объявления, частичная (`--id`) дополняет их. Штамп `--install` один раз добавляет `icons.yaml` в секцию `Icons` манифеста.
- Godot в `--headless` использует dummy-рендерер и не отдаёт изображение, поэтому обёртка открывает окно 1×1. После записи PNG выполняется `--headless --editor --import`: без `.import` файл не загрузится как `Texture2D`.

## Представление

`Sandbox.CommandPanel` загружает `Icon` вместо кадра корневого part. Кнопка производства использует составную иконку продукта, если у его модели она есть, и сохраняет собственный `action.Icon` для действий без такой модели. Кеш иконок остаётся по индексу типа юнита.

Ограничения: иконка одна на модель и не различает владельца, состояние повреждения, апгрейды и направление; для юнитов с общей моделью она общая. Это статичный кадр idle, а не анимация.
