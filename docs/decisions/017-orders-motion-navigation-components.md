# 017. Приказы, движение и навигационный агент в ECS

Дата: 2026-11-05. Реализован E4b после [Spatial/Health](016-spatial-health-components.md). [Проверки и стоимость](../verification/018-orders-motion-navigation-ecs.md), [план миграции](../research/ecs-selection/migration.md). E4 в целом ещё не завершён.

## Разделение состояния

Unit storage получает три внутренних struct-компонента:

- `OrderState`: активный UnitOrder, признак его наличия, фаза, FIFO отложенных приказов, текущая боевая цель и тик начала приказа. Это состояние исполнения, а не UI или определение команды.
- `MotionState`: точная цель перемещения, признак движения и дробный остаток скорости. SpatialState по-прежнему хранит Position/Previous, Locomotor остаётся в неизменяемом определении.
- `NavigationAgentState`: конечная navcell, cohort/group membership, ожидание, последний прогресс, уступание с deadline, локальная цель и точки локального пути с length/cursor, TerrainStranded.

Из EntityState[] удалены соответствующие поля. Временные ref-return свойства Orders/Motion/Navigation обращаются к единственной изменяемой копии в Frent; они не синхронизируют второй store. Копия EntityState не является snapshot. Компонентные refs остаются внутри участка без Spawn/Delete и не передаются рабочим потокам. После удаления native entity обращаться через старую копию нельзя.

FIFO создаётся по необходимости, ограничение32 и проверка queued waypoint при активации сохраняются. Очередь принадлежит одному actor. Копирование struct-компонента со ссылкой на Queue или массив не является глубоким клонированием; runtime cloning компонентов между actors не поддерживается.

## Локальные пути и общие структуры

Локальные16точек теперь принадлежат NavigationAgentState конкретной entity. В навигационном мире массив создаётся при Spawn; в direct мире ссылка null и буфер не выделяется. Вместо прежнего общего массива `capacity × PathCapacity` используются отдельные небольшие массивы. Это добавляет заголовок массива на навигационного actor, но не требует копирования пути при legacy packed removal и не резервирует путь в direct мире.

Frent переносит компонент вместе с entity при перемещении archetype rows. При удалении объекта из legacy массива обновляется только mapping оставшегося объекта; отдельного Path(Count)→Path(index) больше нет. Рост ёмкости также не меняет владельца пути.

SharedRouteTree, WeightedNavigator, budgets/caches, MotionIndex и локальный поисковый scratch остаются специализированными структурами. `_groupRoutes` по EntityId пока остаётся отдельным per-agent вспомогательным состоянием с канонической сериализацией; его перенос вместе с оставшейся навигационной интеграцией не входит в этот срез. MotionIndex всё ещё использует packed index, его переход на domain mapping остаётся в E4/E5.

## Исполнение

Previous обновляется закрытым ECS-запросом после команд. Direct movement выполняется запросом SpatialState + MotionState + EntityDefinition: у каждой строки своя арифметика, поэтому порядок archetypes не влияет на результат. Счётчик MovingCount также читает MotionState запросом. Непространственные определения в unit storage пока не создаются; наличие Spatial у этого запроса гарантирует UnitDefinition frontend.

Приказы, конфликтующее локальное движение, выбор цели, боевые результаты и выдача ID сохраняют прежний доменный порядок. Изменение хранения не включает Frent.World.Update и не вводит новый scheduler. Навигационные jobs получают прежние карты/запросы; между подготовкой запросов и применением результатов компонентные refs закрыты. Production выполняет структурные изменения после завершённых запросов движения/боя.

Spawn атомарно инициализирует семь компонентов обычного spatial actor или восемь с ProducerState. UnitIdentity и immutable EntityDefinition не меняются. Native reuse не переиспользует domain EntityId, очередь, путь, ожидание или остаток скорости.

## Контракты и следующий срез

WorldCommand/Session, UnitDefinition, YAML и опубликованные poses остаются прежними. Хеширование читает компоненты в прежнем порядке и не включает storage layout или неиспользованные хвосты буферов. Форматы catalog7/direct7/nav11 и эталонные hashes сохранены.

Weapon mounts/cooldowns, Owner и presentation пока остаются в legacy state. Следующий срез — Combat/Presentation, затем удаление оставшихся миграционных views/массивов и переработка mapping. Заменяемые системы вводятся по конкретным потребителям, без универсального IEcsWorld/Actor wrapper. Players и projectiles не обязаны использовать этот Frent.World.
