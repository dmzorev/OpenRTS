Для Hidden и Explored после каждого обновления совпадают статусы всех клеток/игроков и признак положительного покрытия. Число contributors может отличаться: объединённый пакет учитывается одним вкладом.

Отдельные миры с включённой и выключенной группировкой выполняют один журнал и дают одинаковый Report. Проверено, что Visible вообще не создаёт FogOfWar, Explored не содержит неизвестных клеток внутри карты и сохраняет скрытие чужих объектов. Источники для красивого отображения передаются только своему viewer. Все10 Fog checks прошли; старые пять ECS baseline-трасс совпали без перебазирования чисел. Для исторических no-fog baseline-тестов из контента удаляется только новый inline Vision: они продолжают проверять прежние игровые данные; реальные радиусы отдельно входят в fingerprint и проверяются новыми тестами.

Первый полный прогон обнаружил ожидаемое изменение пяти baseline-хешей из-за добавления Vision в content. Вместо принятия новых чисел исторические fixtures отделены от нового опционального свойства. Повторный полный прогон, включая длительный сценарий навигации, прошёл без падений.

`--verify-fog-match` прошёл: меню передаёт скрытый режим в основной матч, у стартовых юнитов есть заданный обзор, чужая база скрыта, команды ограничены выбранной стороной. Стандартный `--verify-match-setup` проверяет три пункта Fog и доступность визуальной настройки; его прежняя проверка полной карты запускается с явно выбранным Visible. Проверки AI-журналов также явно используют Visible, чтобы не подменять их прежние условия; новые критерии качества стратегии AI в неизвестной карте здесь не вводились. `tools/verify.py` дополнен проверкой скрытого матча и прошёл целиком, включая прежние проверки представления/боя/авиации/строительства/карт и обоих AI-профилей.

## Производительность

Команда: `DOTNET_TieredCompilation=0 ./tools/dev.sh benchmark --fog-groups-benchmark --count=10000 --ticks=160` (dev.sh уже задаёт отключение tiered compilation). Release, .NET10.0.105, arm64 Apple M3 Max. Мир512×512 клеток по1024, 2 игрока, все10 000 источников owner1; radius6144, телаNone, без навигации и оружия. 32 прогревочных +160 измеряемых тиков после приказов; время — только World.Step, не hash/frame/render. Полный [вывод](fog-groups/benchmark.txt).

| Профиль | Обычный p50, мс | Группы p50 | Обычный p95 | Группы p95 |
| --- | ---: | ---: | ---: | ---: |
| Плотные ряды, pitch256, общий сдвиг128 | 8.220 | 2.413 | 8.486 | 2.528 |
| Разреженные ряды, pitch2048, общий сдвиг128 | 8.088 | 2.438 | 8.594 | 2.547 |
| Плотные ряды, разные направления к общей цели | 8.935 | 9.088 | 9.291 | 9.420 |

В каждом A/B совпал итоговый state hash. На измеренной общей трансляции получено около3.4× ускорения; в последнем измеряемом тике157 пакетов получили маску из кэша, индивидуальные круги не растеризовались. В деформирующемся профиле используется прежний путь: ускорения нет, добавлена небольшая стоимость проверки пригодности (~1.7% p50 в этом прогоне). Во всех строках32байт/тик на owner thread. Ранний вариант fallback выделял около1MiB/тик из-за захватывающего lambda при проверке membership; заменён проходом по отсортированным ID, после чего лишние аллокации исчезли.

Это разведочный A/B, одновременно выполнялась длинная регрессия навигации. Числа характеризуют эти входы, а не любой бой10 000 юнитов. Ключевой критерий — точность результата и отсутствие лишних аллокаций при разрушении формации. GPU-производительность10 000 красивых кругов не измерялась; симуляционный выигрыш не распространяется автоматически на рендер, viewer-выдачу, большие радиусы и частые смены membership.

## Границы

Активные групповые маски и фазовый кэш имеют отдельные лимиты по1Mi интервалов; недостаток бюджета переключает соответствующий пакет на индивидуальные источники. Пакеты с менее4 источниками, нерегулярным движением или более65536 исходных строк тоже используют fallback. При введении occlusion/terrain LoS эти маски должны получить иной ключ/алгоритм. Скрытность, радары, память зданий и knowledge-aware навигация остаются за пределами этой работы.
