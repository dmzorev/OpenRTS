# Проверка групповых мест и уступания

Историческая версия назначения по свободным местам. Её заменили [пространственное назначение и новая навигация](006-compact-group-navigation.md); прежние замеры относятся к прежним исходникам и сценарию.

3 ноября 2026 года, macOS ARM64, Apple M3 Max, .NET SDK 10.0.105, Godot 4.7.2 .NET.

- Debug solution собран без ошибок и предупреждений. Прошли 20 проверок DeclarativeContent и 46 проверок OpenRTS, включая 10 новых групповых сценариев.
- Плотная стартовая группа из 36 юнитов полностью завершает приказ. Конечные позиции имеют промежутки для прохода.
- Девять участников занимают отдельные места; семь полностью проходят одноклеточное отверстие без индивидуальных глобальных полей.
- Встречные юниты обходят друг друга на открытой полосе. В отдельном коридоре один отступает к боковому карману, после чего оба заканчивают исходные приказы.
- Коридор без места для разъезда остаётся безопасным затором. Точная занятая индивидуальная цель сохраняет ожидание.
- Проверены отказ всего приказа при закрытом якоре и недостатке подходящих мест, NoRoute для участников из другой компоненты рельефа, прежние пределы публичных целей GridNavigator.
- Проверены индивидуальное переназначение, новый групповой приказ во время перехода, Spawn, Destroy, правка карты и копирование активного локального пути при уплотнении массива.
- Малые сценарии проверяют геометрию на концах и четвертях интерполяции каждого тика. Число локальных поисков ограничено 64.
- Сценарий 10000 сущностей, включая MoveGroup на тике 41, сравнивается при 1/2/4 workers и обратном выполнении. Установившееся движение с фиксированной целью по-прежнему не выделяет managed память в вызывающем потоке Step; это не утверждение о перестроении групповых полей.
- Полный verify сравнивает headless и Godot на 1 и 10000 сущностях при 15/120 FPS; прежние проверки прямого режима и контента сохраняются.
- Настоящий графический backend Godot проверен на 10000 сущностях при 1 и 4 workers: препятствия, интерполяция, переиспользование MultiMesh и итоговый хеш совпадают с headless.
- В Release одинаковы хеши при 1/4 workers на 1000, 10000 и 100000 сущностях после 128 тиков. Дополнительно выполнены 1024 тика на 36 сущностях с завершением всех приказов и 4096 тиков на 10000 сущностях: остались 9622 действующих приказа, 9465 ожидают. Это фиксирует ограничение пропускной способности, а не успешное завершение большой группы.
- Итог на 10000 сущностях после 64 тиков: `3183214E191599791921515C0394F6C65386100AB70B5B156C6FB2E2CC042C19`.

```sh
./tools/dev.sh verify
./tools/dev.sh run --navigation --workers=4
./tools/dev.sh run --verify-simulation --navigation --workers=4 --count=10000 --ticks=64
./tools/dev.sh benchmark --navigation --workers=4 --count=10000 --ticks=128
```
