# Проверка точного движения и независимой навигационной сетки

> Историческая фиксация этапа движения. Слой представления добавил семантические поля и новые версии хеша; актуальные проверки — [008](008-presentation.md). Замеры/SHA здесь относятся к предыдущему составу мира.


4 ноября 2026 года. macOS ARM64, Apple M3 Max, .NET SDK 10.0.105, Godot 4.7.2 .NET. Это новая модель тел и движения, сравнивать её время с прежним клеточным footprint как ускорение нельзя.

Сборка Debug и Release прошла без ошибок и предупреждений. Прошли 20 проверок DeclarativeContent и 76 OpenRTS, всего **96**; полный verify завершился успешно.

## Функциональные сценарии

- Произвольные координаты создания, цель внутри той же navcell, точное прибытие и немедленный retarget без окончания клеточного ребра.
- Одинаковая свободная траектория при terrain CellSize = 1024 и 4096. Нормированная скорость под углом, отличным от 0/45/90°, без округления цели.
- Несколько тел в одной coarse navcell. Компактный приказ для 25 участников при 16 navcells имеет те же места/траектории, что подробная карта того же размера.
- Закрытый диагональный угол не пропускает тело. Путь через стену достигает произвольного off-center endpoint. Непригодная цель отвергается с учётом радиуса, а не только свободного центра клетки.
- Пересекающиеся межтиковые траектории отвергаются даже при безопасных endpoints. Малые групповые сценарии проверяют интерполяцию.
- Строительство проверяет текущие тела. Ревизия учитывает тело у точной групповой цели, когда блокируется соседняя клетка. Уступание завершается по timeout даже при застройке будущего кармана. Обмен местами сохраняет независимую высоту каждого участника.
- Сохранены проверки общего переноса 10000 участников на открытой карте, cached allocations, compact gathering, одноклеточных проходов, packed removal, событий, потока, паузы и последовательных/параллельных полей.

Длительный профиль 1000 участников через четырёхклеточную стену завершил все приказы на тике 22156, без NoRoute. Регрессия проверяет и полный конечный набор мест: остановка вследствие отказа не считается прибытием. Лимит проверки увеличен с 16384 до 32768 после явного изменения физики. Прежняя версия завершала на тике 10000; снижение пропускной способности зафиксировано, её оптимизация отложена по запросу пользователя.

## Сквозная проверка

`./tools/dev.sh verify` собирает Debug, запускает проверки, сверяет импорт/контент, статический MultiMesh, прямой режим и реальное расписание. Навигационный профиль 1 объекта идёт до 128 тиков,10000 — до 256 тиков при 1/4 workers, reverse execution и Godot15/120 FPS. Any-angle группа достигает стены раньше старого общего Manhattan-переноса. Прежний Debug-профиль 768 превысил 60 секунд; длина изменена по фазе сценария, а не по конечному хешу. Полное прохождение большого стресса 10000 в новой модели не проверено и не объявляется завершённым.

Дополнительный native запуск использует графический backend, ту же симуляцию и автоматические проверки MultiMesh/интерполяции. Обработчики камеры/паузы/темпа/очереди шагов проверяются программно через InputEvent; это не физический ручной playtest клавиатурой/мышью. Увеличивать/уменьшать время и камеру можно прежними клавишами, см. [управление](005-sandbox-controls.md).

Оба нативных сценария прошли: 36 объектов / 1400 тиков и 10000 объектов / 256 тиков при 4 workers. Их отчёты совпали с headless, в том числе между Debug Godot и Release headless. Итоговый хеш большого сценария:
`9CFAA42315AA0AE70BFBEFDEA55AC513300DFD2A2BFCA77C8AEBBC533FFC635A`.

```sh
./tools/dev.sh verify
./tools/dev.sh run --navigation --count=1
./tools/dev.sh run --navigation --workers=4
./tools/dev.sh headless --navigation --count=10000 --ticks=256 --workers=1
./tools/dev.sh run --verify-simulation --navigation --count=10000 --ticks=256 --workers=4
./tools/dev.sh benchmark --navigation --count=10000 --ticks=256 --workers=4
```

## Границы результата

Один радиус 256, бинарные полные terrain samples, минимум CellSize514, нет частичной геометрии, разных тел, Locomotor/весов/CanStop, отношений игроков, fog knowledge, AoE или боевых фаз. Локальный поиск ограничен, не гарантирует разрешение заторов. Прежние результаты 10000/90000 тиков относятся к исторической версии 005.

## Замеры текущих исходников

Один последовательный запуск на профиль, Release, Apple M3 Max, DOTNET_TieredCompilation=0, прогрев 64 тика. Измерен только World.Step, без кадров, графики, хеширования и боя. Аллокации относятся к вызывающему потоку. Не все fallback/JIT ветви покрываются прогревом; максимум включает массовое назначение и подготовку путей.

| --- | --- | --- | --- | --- | --- |
| 10000 / 64 | 1 | 10.3321 | 22.8858 | 0 | Приказы ещё выполняются |
| 10000 / 256 | 1 | 13.8291 | 109.7495 | 1 | Приказы ещё выполняются |
| 10000 / 256 | 4 | 13.7143 | 110.0654 | 1 | Приказы ещё выполняются |
| 1000 / 256 | 4 | 2.1322 | 7.7222 | 1 | Приказы ещё выполняются |
| 36 / 1400 | 4 | 0.2267 | 3.3871 | 1 | 1116 |

Профиль 10000/64 — общий свободный перенос. Профиль 10000/256 уже строит terrain tree и исполняет локальные контакты: сокращённый verify действительно пересёк границу фаз. Хеши 1/4 workers совпали. Значения не включают всю игру и не означают такую же стоимость в Debug; предыдущий таймаут Debug768 сохраняется как выявленное ограничение, а не скрывается увеличением лимита. Массовая подготовка даёт пик около 110 мс; оптимизация расходов/бюджета и завершения больших толп остаётся следующей работой.

Все эти профили имеют FailedRoutes=0. Только 36/1400 является полным измеренным прохождением в таблице; завершение 1000 на 22156 подтверждено отдельной регрессией без замера её Step. Полного завершения 10000 в новой модели таблица не доказывает.
