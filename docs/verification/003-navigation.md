# Проверка навигации и резерваций

Историческое описание первой сеточной версии. Текущие групповые приказы, локальные обходы, расширенная карта и новые измерения описаны в [продолжении](004-group-destinations.md); прежние хеши и замеры относятся к старым исходникам и сценарию.

3 ноября 2026 года. macOS ARM64, Apple M3 Max, .NET SDK 10.0.105, Godot 4.7.2 .NET.

- Debug solution и Release headless собраны без ошибок и предупреждений.
- Прошли 20 проверок DeclarativeContent и 36 проверок OpenRTS, из них 18 посвящены навигации.
- Проверены неизменяемость и границы карты, известные кратчайшие расстояния, закрытая цель и ограниченный бюджет полей.
- Последовательное и параллельное исполнение с обратным порядком задач дают одинаковые поля. На сетке 1024×1024 для четырёх целей полностью посещены 4194304 клетки.
- Один юнит и группа из пяти юнитов с различными целями проходят одноклеточный проход. В групповом тесте все достигают своих мест, геометрические footprints не накладываются и результаты совпадают для разных исполнителей.
- Проверены запрет общей занятой клетки, запрет встречного обмена, смена цели посередине перехода и сохранение резервирования. Для пересечений между тиками отдельно проверяются интерполированные положения.
- Регрессионный пример с перпендикулярным входом в освобождённую клетку ждёт до следующего тика и больше не создаёт пересечение.
- Занятая клетка не застраивается, неверный Spawn отклоняется, Destroy освобождает резерв. Открытие препятствия не использует устаревшее поле.
- Отдельный сценарий доставляет 70000 событий NoRoute с явным бюджетом очереди, превышающим стандартный лимит. Стенд выбирает такой бюджет по числу юнитов.
- Разный порядок плотного массива не меняет конфликты. Параметры бюджета и кэша входят в хеш; число workers и порядок задач не входят.
- Снимок карты старого читателя остаётся неизменным после правки. Проверена остановка сессии с большим слоем и параллельным поиском.
- На 10000 юнитах сравниваются состояния при 1, 2 и 4 workers, включая обратное выполнение. Установившийся Step с готовыми полями не выделяет managed память в вызывающем потоке.
- Headless и Godot сравниваются на 1 и 10000 объектах при лимитах 15/120 FPS и 1/4 workers. Сохраняются также прежние проверки прямого режима.
- Настоящий графический backend проверен на 1 объекте с одним worker и на 10000 объектах с одним и четырьмя workers. Проверены количество и последняя позиция препятствий, интерполяция позиций и совпадение хеша с headless.
- Debug и Release на 10000 объектах после 64 тиков навигационного сценария дают `5FA1CD80D6F859C2B278DCD4EBC760D8E870DBA091F2AA2E7115189AF3CF7E99`. На 128 тиках при одном и четырёх workers — `AE4533DAF0B28408DFB3E981B788056CFAC179D7E0164680147D31D67DE79A54`.

Команды:

```sh
./tools/dev.sh verify
./tools/dev.sh run --navigation --workers=4
./tools/dev.sh run --verify-simulation --navigation --workers=4 --count=10000 --ticks=64
./tools/dev.sh headless --navigation --workers=1 --count=10000 --ticks=64
./tools/dev.sh headless --navigation --workers=4 --reverse-jobs --count=10000 --ticks=64
./tools/dev.sh benchmark --navigation --workers=4 --count=10000 --ticks=128
```

[Сырые измерения](../research/navigation-and-crowds/measurements.json) включают исходные SHA-256, параметры JIT, первый и максимальный тик, число ожидающих, число полей и посещённых клеток. Короткие замеры не проверяют всю RTS: исключены кадры, Godot, бой и масса независимых маршрутов. Новые цифры с фиксированным JIT не сравниваются напрямую с историческими замерами этапа 2.

Не реализованы кооперативное разрешение встречных заторов, разные размеры footprint, формации, иерархия секторов и частичная инвалидация карты. Эти ограничения не скрываются успешным проходом пяти юнитов или общим числом объектов.
