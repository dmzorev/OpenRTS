# OpenRTS

Самостоятельный RTS движок на C# с независимой симуляцией и интеграцией с Godot .NET. Код движка распространяется под MIT.

Реализованы рабочий каркас, фиксированная симуляция и базовая сеточная навигация. Есть владельцы, семантические анимации/состояния, устойчивые ID, команды, RNG, создание и удаление объектов, общие поля маршрутов, изменения проходимости, точные позиции и движение под произвольным углом, компактные групповые назначения, swept проверки тел и ограниченное уступание. Godot читает кадры отдельного потока симуляции. Добавлены активные приказы/очередь, корректировка недоступных целей и оружие с независимыми орудиями, снарядами, burst, бронёй, AoE и ремонтом. Добавлены кастомные способности, autocast, панели типов и параллельные очереди производства с C&C размещением. Плотных формаций и общего решения произвольных заторов пока нет.

OpenRTS создаётся независимо от OpenRA. Совместимость с его API, модами, форматами и реплеями не требуется. OpenRTSv1 остаётся отдельным исследовательским проектом; извлечённый из OpenRA код не переносится в MIT ядро.

Из Hyperfleets перенесена самостоятельная MIT библиотека DeclarativeContent с тестами и уведомлением о лицензии. [Происхождение и SHA-256](docs/vendor/declarative-content.json) фиксируют точную версию импорта. Проект не требует наличия Hyperfleets для сборки.

`OpenRTS.Core` содержит цикл симуляции, сессию, команды, размещение, пространственное состояние и ECS на закреплённом MIT пакете Frent 0.9.1-beta. Игры могут задавать свои команды, компоненты и правила поверх Core. `OpenRTS.Gameplay` предоставляет готовую RTS-сборку `SimulationWorld`, поиск пути, приказы, бой и производство. `OpenRTS.Content` компилирует YAML в определения Gameplay и отделяет `Actions.Definitions` от `ActionPanel.Buttons`. Прямой потребитель создаёт мир через `using`. Сессия освобождает принадлежащий ей мир сама. [Граница сборок](docs/decisions/023-core-and-gameplay.md) · [Лицензия Frent](docs/vendor/frent-license.txt).

Godot служит для ввода, сцены, интерфейса и звука. Headless и Godot используют одни определения и ту же симуляцию. Выделенный поток владеет миром; представление читает закреплённые кадры и интерполирует позиции. События передаются отдельно. Поля маршрутов строятся через ограниченный Parallel.For; результат пакета применяется после общего барьера.

Целевые требования: desktop, наземный мир 2.5D, 10000+ объектов и большие карты. Реальная стоимость движения, боя, поиска путей и отображения будет измеряться раздельно по мере реализации систем.

Требуются .NET SDK 10.0.105 (допускается более новый patch этой feature band), Godot 4.7.2 .NET, Bash и Python 3 для сквозных проверок. При первом запуске пакеты восстанавливаются из NuGet. На macOS Godot также ищется в соседнем `Godot_mono.app`; для другого расположения задайте `OPENRTS_GODOT` полным путём к исполняемому файлу.

```sh
./tools/dev.sh build
./tools/dev.sh test
./tools/dev.sh headless
./tools/dev.sh headless --simulate --count=10000 --ticks=64
./tools/dev.sh verify
./tools/dev.sh run                        # Полигон зданий
./tools/dev.sh run --showcase             # Прежний боевой полигон
./tools/dev.sh run --count=10001
./tools/dev.sh run --navigation --workers=4
./tools/dev.sh run --verify-simulation --count=10000 --ticks=64
./tools/dev.sh headless --navigation --workers=1 --count=10000 --ticks=64
./tools/dev.sh benchmark --count=10000 --ticks=128
./tools/dev.sh benchmark --navigation --workers=4 --count=10000 --ticks=128
./tools/dev.sh benchmark --size-benchmark --count=10000 --ticks=128 --workers=1
./tools/dev.sh headless --production --ticks=160
./tools/dev.sh run --verify-actions
./tools/dev.sh editor
```

Команды сами переходят в корень репозитория. `test` запускает два исполняемых проекта проверок; `dotnet test` их не выполняет. `verify` проверяет импорт библиотеки, контент, движение, навигацию и воспроизводимость в двух хостах. `benchmark` собирает Release headless и измеряет только World.Step, без публикации кадров и графики. Только для замера он устанавливает `DOTNET_TieredCompilation=0`, чтобы исключить смену уровня JIT в коротком опыте.

По умолчанию `./tools/dev.sh run` открывает top-down skirmish. Синий и красный игроки получают по 5000 кредитов, строительной площадке и инженеру. Нейтральный игрок владеет шахтами, вышками и декорациями. Пока доступны обе стороны. Q инженера — ремонт, W — захват. Контекстный ПКМ по чужой или нейтральной захватываемой постройке тоже отдаёт приказ захвата. [Правила экономики и захвата](docs/decisions/020-players-economy-capture.md), [проверки](docs/verification/021-players-economy-capture.md).

В skirmish **F10** или кнопка на HUD переключают «Военный терминал» между правой и нижней раскладками. ЛКМ и перетаскивание на миникарте перемещают камеру. Она также прокручивается у края игрового поля. Полосы здоровья видны у выбранных и повреждённых объектов. HUD показывает кредиты и энергию стороны, которой сейчас управляет игрок. **Esc** отменяет наведение или открывает меню матча с настройками камеры и индикаторов. **F12** открывает диагностику с ресурсами обеих сторон и управлением тиками. Раскладка и настройки сохраняются между запусками.

В skirmish выберите инженера и здание на панели (E/R/T/Y/U), затем разместите полупрозрачный проект ЛКМ. Shift добавляет стройку в очередь и позволяет сразу разместить следующий проект. ПКМ по проекту или фундаменту отправляет выбранных строителей на помощь. Выделенный проект отменяется через Delete или кнопку панели. Construction Yard умеет строить на месте в пределах показанного кольца (T/Y/U/I), а Q–E оставляют размещение готовых зданий. [Устройство стройки на месте](docs/decisions/022-on-site-construction.md).

`--buildings` открывает прежнюю лабораторию зданий. Выбор типа внизу + B/ЛКМ бесплатно размещает здание (Shift — повторять), Delete убирает без руин, Backspace разрушает. O открывает дверь, C/F запускают отладочные визуальные клипы. W переключает состояние работы, когда эта клавиша не занята кастомным действием. Кнопка очистки убирает только визуальные руины. Эти инструменты редактирования недоступны в skirmish. `--showcase` открывает боевой полигон с девятью типами двух владельцев (20 объектов).

ЛКМ/двойной клик/рамка выбирают юнитов; Shift добавляет выбор или приказ в очередь. ПКМ — идти/атаковать, A/M + ЛКМ — назначить агрессивное движение/обычный ход, S/H — Stop/Hold, Ctrl+1…9 и 1…9 — контрольные группы. Клик в недоступную область корректируется к достижимому месту. Камера на стрелках/СКМ/колесе, Пробел центрирует выбор. Q автоматчика — граната. ПКМ по кнопке оружейной способности включает/выключает autocast; контекстный ПКМ по повреждённому союзнику применяет зарегистрированный ремонт. [Все сочетания, кадры и проверки](docs/verification/011-orders-and-controls.md).

Панель типов показывает иконки и количество: Tab/Shift+Tab переключают активный тип. Кастомные хоткеи Q–Y настраиваются и имеют приоритет над стандартными. Бараки строят пехоту, завод — технику, Construction Yard — здания и инженеров в параллельных очередях. Shift добавляет 5 заказов, ПКМ по кнопке — повторяемую задачу. Стопка очереди: ЛКМ снимает 1, Shift+ЛКМ — 5, ПКМ — всю. ПКМ по земле задаёт производителю rally. Готовое здание размещается ЛКМ по его кнопке с отметкой «✓» в skirmish и «ГОТОВО» на полигоне. Цена и политика списания применяются к кредитам владельца. При дефиците энергии производство идёт вдвое медленнее, оружие зданий отключается. [Панель, YAML и очереди](docs/verification/014-actions-and-production.md), [экономика](docs/decisions/020-players-economy-capture.md).

Игровые YAML объявления — units.yaml и weapons.yaml; адаптерные эффекты — effects.yaml; модели/части/последовательности — в models.yaml; ресурсы SpriteFrames/Texture2D — в sandbox/resources. Core знает только именованные действия, направления и состояния. Графика не определяет коллайдер или игровой хеш. Для чистого headless того же полигона: `./tools/dev.sh headless --showcase --ticks=12`.

Стандартные run/verify импортируют ресурсы Godot после сборки.

Godot проект находится в `sandbox/project.godot`. Пример контента — `sandbox/content/units.yaml`. Параметр `--count` задаёт число сущностей диагностического мира, по умолчанию 10000. Стенд обновляется на 25 Гц. Для прямого диагностического режима укажите `--count=10000`; в нём ПКМ задаёт цель всем юнитам, Пробел выбирает случайные цели, R перезапускает мир, Esc закрывает окно.

`--navigation` включает стену с проходом и проверку круглых тел вдоль всего движения. Сетка используется для поиска по рельефу; позиции и цели точные, движение под произвольным углом. Несколько тел могут находиться в одной крупной навигационной клетке. ПКМ задаёт компактную область группового назначения, Пробел меняет сторону, B открывает или блокирует клетку под курсором. Препятствие не может пересекать существующее тело. Оранжевые блоки показывают актуальный снимок проходимости, интерфейс показывает действующие приказы, ожидание, обходы и уступания.

MoveGroup собирает толпу около точки и не сохраняет исходные смещения. Конечные места назначаются пространственно заранее в мировых координатах, независимо от размера navcell; около цели возможны ограниченные локальные обмены для освобождения прохода. Плотный регулярный блок с одинаковыми точными сдвигами движется общим проверенным пакетом. Иначе используются общие данные поиска по рельефу и личные маршруты. В пути форма группы не фиксируется. Размер тела задаётся Unit.Body (круг/прямоугольник), локальный обход имеет шаг256, шаг мест группы не меньше1024 и размера тела с зазором; NavigationGrid.CellSize задаётся отдельно. N1 добавляет Locomotor и веса грунта, N2 — размеры, многоклеточные объекты, частичные препятствия и ограничения поверхности. Предопределённые формации, туман войны, полные режимы подгрупп и секторная иерархия пока не реализованы. Для проверки коротких точных приказов удобно запустить `./tools/dev.sh run --navigation --count=1`.

Интерактивная навигация стартует со стоящих объектов и ждёт приказа. Колесо приближает/удаляет камеру около курсора, СКМ перетаскивает карту, WASD/стрелки перемещают её. `+`/`−` меняют темп ×0,125–×8, P — пауза, N — одиночный тик. Ускорение меняет реальное расписание, сохраняя размер логического шага и результат на одном тике. [Проверки управления](docs/verification/005-sandbox-controls.md).

`--verify-buildings` проверяет footprint/состояния/радар/двери и пакеты 10000 зданий, а с `--capture=/tmp/buildings/final.png` сохраняет нативные кадры и проверяет перекрытие юнита пикселями. `./tools/dev.sh headless --buildings --ticks=24` выполняет тот же сценарий без графики.

`--verify-controls` проверяет обработчики камеры и темпа. `--verify-simulation` выполняет конечный сценарий и печатает хеш состояния; `--ticks` задаёт его длину. В обычном запуске симуляция работает до выхода. `--fps` ограничивает только отображение. Статический режим `--verify` сохранён для регрессии первого этапа. Диагностический стенд использует один MultiMesh; полигон — пакеты по текстурам, без Node на каждую сущность. Пространственное разбиение для большой карты появится вместе с управлением видимостью.

При ограниченном доступе к сети `OPENRTS_NUGET_SOURCE` позволяет передать локальный NuGet feed при восстановлении пакетов. Сам Godot SDK должен быть доступен SDK resolver через NuGet или локальный кэш `.packages`. Это настройка окружения, пути к Hyperfleets не входят в проекты.


`./tools/dev.sh headless --skirmish --ticks=1800` выполняет проверочный журнал захвата и строительства на той же карте. Интерактивный skirmish стартует без автоматических приказов.
