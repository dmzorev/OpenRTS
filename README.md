# OpenRTS

Самостоятельный RTS движок на C# с независимой симуляцией и интеграцией с Godot .NET. Код движка распространяется под MIT.

Реализованы рабочий каркас и минимальная симуляция: фиксированные тики, устойчивые ID, команды, RNG, прямое движение, создание и удаление объектов. Godot отображает 10000 движущихся объектов из отдельного потока симуляции. Навигация, столкновения и бой ещё не реализованы.

OpenRTS создаётся независимо от OpenRA. Совместимость с его API, модами, форматами и реплеями не требуется. OpenRTSv1 остаётся отдельным исследовательским проектом; извлечённый из OpenRA код не переносится в MIT ядро.

Из Hyperfleets перенесена самостоятельная MIT библиотека DeclarativeContent с тестами и уведомлением о лицензии. [Происхождение и SHA-256](docs/vendor/declarative-content.json) фиксируют точную версию импорта. Проект не требует наличия Hyperfleets для сборки.

Godot служит для ввода, сцены, интерфейса и звука. Headless и Godot используют одни определения и ту же симуляцию. Выделенный поток владеет миром; представление читает закреплённые кадры и интерполирует позиции. События передаются отдельно. Пул рабочих потоков для тяжёлых систем относится к следующему этапу.

Целевые требования: desktop, наземный мир 2.5D, 10000+ объектов и большие карты. Реальная стоимость движения, боя, поиска путей и отображения будет измеряться раздельно по мере реализации систем.

Требуются .NET SDK 10.0.105 (допускается более новый patch этой feature band), Godot 4.7.2 .NET, Bash и Python 3 для сквозных проверок. При первом запуске пакеты восстанавливаются из NuGet. На macOS Godot также ищется в соседнем `Godot_mono.app`; для другого расположения задайте `OPENRTS_GODOT` полным путём к исполняемому файлу.

```sh
./tools/dev.sh build
./tools/dev.sh test
./tools/dev.sh headless
./tools/dev.sh headless --simulate --count=10000 --ticks=64
./tools/dev.sh verify
./tools/dev.sh run
./tools/dev.sh run --count=10001
./tools/dev.sh run --verify-simulation --count=10000 --ticks=64
./tools/dev.sh benchmark --count=10000 --ticks=128
./tools/dev.sh editor
```

Команды сами переходят в корень репозитория. `test` запускает два исполняемых проекта проверок; `dotnet test` их не выполняет. `verify` проверяет импорт библиотеки, загрузку контента, статические экземпляры и воспроизводимость движущихся миров в двух хостах. `benchmark` собирает Release headless и измеряет только World.Step, без публикации кадров и графики.

Godot проект находится в `sandbox/project.godot`. Пример контента — `sandbox/content/units.yaml`. Параметр `--count` задаёт число сущностей диагностического мира, по умолчанию 10000. Стенд обновляется на 25 Гц; ПКМ задаёт цель всем юнитам, Пробел выбирает случайные цели, R перезапускает мир, Esc закрывает окно. Юниты пока могут проходить друг через друга.

`--verify-simulation` выполняет конечный сценарий и печатает хеш состояния; `--ticks` задаёт его длину. В обычном запуске симуляция работает до выхода. `--fps` ограничивает только отображение. Статический режим `--verify` сохранён для регрессии первого этапа. Стенд использует один MultiMesh; пространственное разбиение для большой карты появится вместе с управлением видимостью.

При ограниченном доступе к сети `OPENRTS_NUGET_SOURCE` позволяет передать локальный NuGet feed при восстановлении пакетов. Сам Godot SDK должен быть доступен SDK resolver через NuGet или локальный кэш `.packages`. Это настройка окружения, пути к Hyperfleets не входят в проекты.
